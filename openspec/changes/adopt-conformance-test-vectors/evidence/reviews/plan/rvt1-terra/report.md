**Verdict: REJECT.** The plan needs revisions before approval. Its proposed comparator cannot preserve the existing comparison contract as written, its equivalence gate occurs too early, and the selected JSON and policy-rejection fixtures do not fit the specified harness.

1. **P1 — The comparator is in the wrong module for delegation.**  
   [proposal.md:73](openspec/changes/adopt-conformance-test-vectors/proposal.md:73) places the comparator in `xacml-conformance-tests`, while [tasks.md:12](openspec/changes/adopt-conformance-test-vectors/tasks.md:12) requires production classes in `xacml-test` to delegate to it. The dependency runs the other way: [xacml-conformance-tests/pom.xml:16](xacml-conformance-tests/pom.xml:16) depends on `xacml-test`. Test-source classes are also unavailable to the upstream module.  
   **Smallest fix:** Place the shared comparator in an upstream module accessible to both, or keep the existing public utility comparators and narrow the “one comparator” requirement. Specify how the existing JAXB-typed public methods delegate.

2. **P1 — `ResponseContext` loses distinctions the current comparators check.**  
   [spec.md:41](openspec/changes/adopt-conformance-test-vectors/specs/conformance-suite-harness/spec.md:41) requires model-only comparison of obligations and advice as multisets. But [Result.java:341](xacml-core/src/main/java/org/xacml4j/v30/Result.java:341) merges entries with the same ID, and [Result.java:279](xacml-core/src/main/java/org/xacml4j/v30/Result.java:279) keys included categories by category ID. The existing JAXB comparator can distinguish repeated obligations and repeated categories; its tests exercise both, for example [Xacml20TestUtilityTest.java:88](xacml-test/src/test/java/org/xacml4j/v20/Xacml20TestUtilityTest.java:88) and [Xacml30TestUtilityTest.java:150](xacml-test/src/test/java/org/xacml4j/v20/Xacml30TestUtilityTest.java:150). The proposed `full` fields also omit the 2.0 status detail and resource ID currently checked by [Xacml20TestUtility.java:68](xacml-test/src/main/java/org/xacml4j/v20/Xacml20TestUtility.java:68).  
   **Smallest fix:** Use a lossless comparison representation or retain wire-level comparisons for fields the model cannot preserve. Specify the legacy field set per suite and retain negative tests for multiplicity, resource ID, nested status and status detail.

3. **P1 — The 880-case equivalence gate precedes the comparator change.**  
   [tasks.md:9](openspec/changes/adopt-conformance-test-vectors/tasks.md:9) records old outcomes and compares the new runner in 2.3; 2.4 then replaces the comparators, and 2.5 checks only totals. A changed comparator can therefore pass the earlier gate or produce the same totals while accepting different response fields. Once the old utilities delegate, running both runners may also exercise the same new comparator. This does not prove the field-equivalence requirement at [spec.md:31](openspec/changes/adopt-conformance-test-vectors/specs/conformance-suite-harness/spec.md:31).  
   **Smallest fix:** Keep an independent old comparator or frozen characterization oracle through 2.4, then rerun per-row equivalence immediately before 2.5. Add deliberately altered response-field controls; equal pass/fail totals alone are insufficient.

4. **P1 — The JSON adapter assumes wire formats the existing unmarshallers do not accept directly.**  
   [design.md:48](openspec/changes/adopt-conformance-test-vectors/design.md:48) identifies adding `xacml-json` as the needed integration. The request adapter expects `Category` at the object it receives ([RequestContextAdapter.java:52](xacml-json/src/main/java/org/xacml4j/v30/marshal/json/RequestContextAdapter.java:52)); the response adapter expects `Result` ([ResponseContextAdapter.java:47](xacml-json/src/main/java/org/xacml4j/v30/marshal/json/ResponseContextAdapter.java:47)). The vendored profile example instead has a top-level `Response` array ([IIA022Response.json:1](xacml-conformance-tests/src/test/resources/xacml3.0-ct-v.0.4/IIA022Response.json:1)); the researched request examples use a `Request` envelope. The selected validation fixtures also include standalone invalid requests and responses, not only decision triples.  
   **Smallest fix:** Specify and test the profile envelope and category handling with unmodified source JSON, including negative validation cases. Decide whether this requires a separate `xacml-json` behavior change or an explicitly scoped adapter; do not count a normalized internal format as proof that the public JSON wire format was accepted.

5. **P1 — Patch adoption proceeds with an unresolved redistribution basis.**  
   [design.md:69](openspec/changes/adopt-conformance-test-vectors/design.md:69) assumes patch #1 has the same usable terms as the existing suite, and [tasks.md:23](openspec/changes/adopt-conformance-test-vectors/tasks.md:23) says to add it. Yet [TV4:45](openspec/changes/adopt-conformance-test-vectors/research/tv4-astra-fingerprints-licenses.md:45) distinguishes rights granted to OASIS from a verified downstream fixture license; the exact legacy package grant remains unclear. Download permission does not establish redistribution rights. The same question applies to distributing JSON derived from those fixtures.  
   **Smallest fix:** Make patch and derived-file adoption conditional on a documented, applicable redistribution basis, or defer those files and continue with confirmed project-owned sources.

6. **P2 — The duplicate rule can discard distinct cases.**  
   [provenance spec.md:21](openspec/changes/adopt-conformance-test-vectors/specs/conformance-vector-provenance/spec.md:21) says a file matching any vendored file is not counted as a new case, while its scenario requires the whole case to match. In the current corpus, `oasis20/IIA002` and `IIA003` have byte-identical requests but different policies and responses ([manifest:3](xacml-conformance-tests/src/test/manifest/conformance-manifest.csv:3)). A file-level rule would suppress a distinct test.  
   **Smallest fix:** Deduplicate a case using its complete ordered policy set, request, expected outcome and relevant harness configuration. Add a negative test where one file is shared but the case differs.

7. **P2 — The descriptor cannot represent several selected sources.**  
   [harness spec.md:4](openspec/changes/adopt-conformance-test-vectors/specs/conformance-suite-harness/spec.md:4) requires request, policies and expected response for each row. TV4 identifies policy-only rejection cases among the 23 AuthzForce directories and standalone JSON validation inputs ([TV4:21](openspec/changes/adopt-conformance-test-vectors/research/tv4-astra-fingerprints-licenses.md:21)). The decision-only scenario nevertheless requires `decision-status`, although the Go assertions supply no expected status ([spec.md:52](openspec/changes/adopt-conformance-test-vectors/specs/conformance-suite-harness/spec.md:52)).  
   **Smallest fix:** Add explicit case kinds and required fields for policy rejection, request/response validation and decision evaluation. Add a true decision-only comparison mode, or explicitly record and justify a separately derived status.

8. **P2 — Special verbs lack the data needed to preserve the existing guards.**  
   [design.md:48](openspec/changes/adopt-conformance-test-vectors/design.md:48) defines `syntax-error` and `adjudicated` without the expected defect or replacement decision. Today IIA005 maps only a specific request error, while IIC350/358 replace Permit with NotApplicable only for guarded fixtures ([ConformanceCaseRunner.java:189](xacml-conformance-tests/src/test/java/org/xacml4j/v20/ConformanceCaseRunner.java:189), [ConformanceCaseRunner.java:215](xacml-conformance-tests/src/test/java/org/xacml4j/v20/ConformanceCaseRunner.java:215)). A generic rejection can accept the wrong failure; a section citation alone does not encode an expected decision.  
   **Smallest fix:** Give verbs structured expected phase, defect/status, fixture guard and adjudicated value fields. Port the existing unrelated-error and wrong-fixture negative controls.

9. **P2 — The PIP table cannot express today’s subject-dependent resolver.**  
   [design.md:53](openspec/changes/adopt-conformance-test-vectors/design.md:53) proposes four columns and one 2.0 fact. The [3.0 PIP row](xacml-conformance-tests/src/test/resources/xacml3.0-ct-v.0.4/PIP.txt:1) contains no subject predicate, although the scenario calls it a row for Julius Hibbert. The current resolver returns Physician only for that subject, case-insensitively, and returns nothing for another subject ([Xacml20ConformanceAttributeResolver.java:46](xacml-conformance-tests/src/test/java/org/xacml4j/v20/Xacml20ConformanceAttributeResolver.java:46)).  
   **Smallest fix:** Represent the input subject and matching rule in non-vendored descriptor data, or retain a narrowly scoped resolver. Preserve both the mixed-case positive and different-subject negative tests.

10. **P2 — Named verification is not assigned to tasks, and a descriptor check cannot prove an audit occurred.**  
    The specs and [evidence/README.md:10](openspec/changes/adopt-conformance-test-vectors/evidence/README.md:10) name `TablePipTest` and `VectorAdoptionCheckTest`, but [tasks.md:9](openspec/changes/adopt-conformance-test-vectors/tasks.md:9) and groups 4–8 do not explicitly create them or the adoption checker. `SuiteDescriptorTest` can verify that a section reference exists; it cannot establish that each expected decision was actually checked against that section. Existing rejection, syntax-error and NaN tests also call the old runner and need an explicit migration when its logic is folded in.  
    **Smallest fix:** Assign creation of both named tests and migration of the existing guard tests. Require a per-case reviewed standards rationale as evidence, with a structural test that rejects missing audit records.

11. **P2 — An open option contradicts the vendored-file rule.**  
    [design.md:128](openspec/changes/adopt-conformance-test-vectors/design.md:128) asks whether to remove headers from 34 existing RSA fixtures, despite [AGENTS.md:106](AGENTS.md:106) treating that resource tree as read-only. Regenerating the integrity ledger would not authorize the edit.  
    **Smallest fix:** Remove that option from this plan and record the historical headers and uncertainty in metadata outside the vendored tree. Store patch index entries outside the existing vendored index as well.

12. **P3 — The 2.0 source review stops at patch #1 without dispositioning a later index.**  
    [research/README.md:27](openspec/changes/adopt-conformance-test-vectors/research/README.md:27) summarizes the local v0.4 suite and patch, but [TV4:34](openspec/changes/adopt-conformance-test-vectors/research/tv4-astra-fingerprints-licenses.md:34) also identifies a 2005 v0.5 index and later official changes whose cases were not fully compared.  
    **Smallest fix:** Add a bounded comparison and disposition task for that index and change list before claiming the patch is the complete 2.0 increment.

The unresolved legacy OASIS license blocks the proposed patch and derived-file adoption unless those items are explicitly deferred. The RSA-header question must be resolved in favor of preserving existing files. Running the 72 deprecated cases is a separate scope choice and need not block approval of the rest once the plan states whether they are included.

The design states that **each external download requires explicit maintainer permission** ([design.md:82](openspec/changes/adopt-conformance-test-vectors/design.md:82)); plan approval should remain distinct from those download permissions.
