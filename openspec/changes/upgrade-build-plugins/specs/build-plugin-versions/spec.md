## ADDED Requirements

### Requirement: Pinned plugin versions
The root POM SHALL pin the version of every Maven plugin that the build runs,
including the lifecycle plugins clean, resources, jar, install, and deploy,
so that every supported Maven binary (3.9 and 3.10) resolves the same plugin
versions. A module SHALL NOT override a pinned version without a reason in
its POM.

#### Scenario: Effective POM
- **GIVEN** the reactor
- **WHEN** `help:effective-pom` runs with Maven 3.9.16 and with Maven 3.10.0
- **THEN** both list the same version for each plugin, equal to the pinned version (task 1.3 evidence)

#### Scenario: Offline build with both Maven binaries
- **GIVEN** a local repository that holds the pinned plugins
- **WHEN** the full reactor `clean test` runs offline with Maven 3.9.16 and with Maven 3.10.0 on JDK 21
- **THEN** both succeed with the test counts of the build before the change (task 1.3 evidence)

### Requirement: The upgrade changes no source
Upgrading the plugins SHALL NOT change a tracked file other than the POMs and
the build notes of `AGENTS.md`. A build that does not set
`-Dlicense.skipUpdateLicense=false` SHALL NOT change any file. The generated
JAXB sources SHALL keep the same relative file list and SHALL differ only in
the two XJC header comment lines
(`This file was generated by the Eclipse Implementation of JAXB, v<version>`
and `Generated on: <time>`).
An explicit license header update (`-Dlicense.skipUpdateLicense=false`) is
outside this guarantee: with the old and the new plugin it rewrites files,
including vendored fixtures, and is run only on purpose.

#### Scenario: A default build changes no file
- **GIVEN** the tree with the new POMs
- **WHEN** the reactor `clean test` runs without `-Dlicense.skipUpdateLicense`
- **THEN** `git status` shows no change except the files of the change (task 1.3 evidence, run 002)

#### Scenario: Generated JAXB sources
- **GIVEN** the generated sources of `xacml-xml-jaxb` built with 0.15.1 and with 0.15.3
- **WHEN** the two trees are compared by `compare-generated.sh`
- **THEN** both hold the same files, and every differing line is one of the two XJC header comment lines (task 1.1 evidence, run 004)

#### Scenario: The comparison rejects other differences
- **GIVEN** fixture trees with an added file, a missing file, a changed declaration, a changed other comment, a changed episode file, a binary difference, a missing final newline, an unreadable file, or no tree
- **WHEN** `compare-generated.sh` compares each with the base fixture
- **THEN** each comparison fails, and the comment-only fixture passes (`compare-generated-test.sh`, runs 004 and 005)

#### Scenario: Header update stays opt-in
- **GIVEN** the root POM
- **WHEN** its effective properties are read
- **THEN** `license.skipUpdateLicense` is `true` (task 1.1 and 1.3 evidence)
