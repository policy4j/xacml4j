  ## B. Group 4 Fixes the Donor Would Undo

  The worktree on HEAD has four vital fixes merged from Group 4 (evidence evidence/tests/039-engine-
  equality/ and evidence/tests/035-boolean-lexical/). Adopting the donor files would destroy all four:

  1. Bug 4.10: Fractional Seconds
      • Worktree Implementation:
          • DateTimeDurationUtils.java:77-83, 226-233, 263-270, 306-326 parses and formats BigDecimal
          seconds down to nanoseconds.
          • ISO8601Duration.java:60-63 returns BigDecimal getSeconds().
          • ISO8601DayTimeDurationTest.java:51, 83, 96 asserts BigDecimal seconds.
      • Donor Reversion: b9f114a3:Duration.java:214 truncates seconds to @Unsigned int.
      DateTimeDurationUtils.java:204 casts d.getSeconds() to int and ignores fractional seconds.
  2. Bug 4.11: time-in-range and Unzoned Time
      • Worktree Implementation:
          • ISO8601Time.java:46, 89-93, 123-126 maintains timeZoneDefined boolean. Unzoned times format
          without Z.
          • NonNumericComparisonFunctions.java:114-136 implements XACML 2.0/3.0 time-in-range with midnight
          wrap-around handling and evaluation context implicit offset.
      • Donor Reversion: b9f114a3:ISO8601Time.java drops timeZoneDefined and forces ZoneOffset.UTC
      (outputting "12:00:00Z" for "12:00:00"). b9f114a3:NonNumericComparisonFunctions.java:119-128 reverts
      to naive linear compare ignoring wrap-around and context.
  3. Bug 4.28: UTC-Normalized Temporal Equality/Hash/Order Preserving Zone
      • Worktree Implementation:
          • ISO8601Date.java:157-173: compareTo and equals compare instant() (value.atStartOfDay().
          toInstant(offset)), preserving the parsed timezone offset for toXacmlString().
          • ISO8601DateTime.java:150-164: compareTo and equals compare get().toInstant().
          • ISO8601Time.java:154-170: compareTo and equals compare utcTime().
          • Tested in TemporalEqualityTest.java:34-81.
      • Donor Reversion: Donor records use default field-by-field equality and un-normalized compareTo
      (b9f114a3:ISO8601DateTime.java:179, ISO8601Time.java:108), failing TemporalEqualityTest.
  4. Bug 4.31: Strict yearMonthDuration Validation
      • Worktree Implementation:
          • DateTimeDurationUtils.java:292-295: Strict regex validation rejecting day/time fields:
            if (!v.matches("[+-]?P(?:\\d+Y)?(?:\\d+M)?") || !v.matches(".*\\d[YM]$")) {
                throw new SyntaxException(v, XacmlTypes.YEARMONTHDURATION);
            }

          • Tested in ISO8601YearMonthDurationTest.java:41-44 (rejectsDayComponentsInYearMonthDuration).
      • Donor Reversion: b9f114a3:DateTimeDurationUtils.java:252-258 removes the regex and silently parses
      P30D as P0Y0M.
