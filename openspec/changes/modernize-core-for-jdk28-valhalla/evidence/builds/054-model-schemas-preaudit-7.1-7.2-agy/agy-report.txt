  ## A. Task 7.1: Donor Defects in model/

  ### 1. Confirmation of the Four Named Defects

  #### Defect 1: AttributesSchema.java:101 Invalid Record/Interface Header Construct

  • Citation: b9f114a3:xacml-core/src/main/java/org/xacml4j/v30/model/AttributesSchema.java:101-105
  • Donor Code:
    sealed interface WithAttributes(EntityTypeQualifier typeQualifier,
                          Map<AttributeId, AttributeSchema> attributes)
            extends AttributesSchema permits
    {
        Optional<AttributeSchema> attribute(AttributeId attributeId);
        ...
    }

  • Analysis:
      1. Invalid Java Syntax: In Java (including JDK 21+), interfaces cannot declare record header
      parameter components (...). Only record declarations accept header components.
      2. Empty permits Clause: Line 103 specifies permits immediately followed by {, which is a parser
      syntax error.
      3. Illegal Instantiation: In factory method AttributesSchema.schema(...) at line 64:
        return new WithAttributes(typeQualifier,
                attributes.stream().collect(Collectors.toMap(AttributeSchema::id, a->a)));
      Callers attempt to instantiate new WithAttributes(...), which fails because WithAttributes is
      declared as an interface.
      4. Unimplemented Abstract Methods in Root: Record Root(CategoryId categoryId) implements
      WithAttributes (line 81) implements WithAttributes but does not implement attribute(AttributeId), and
      stubs isValidValue and isValidType to return false, rejecting all attributes and values.
      5. Type Argument Inversion in isValidValue: In WithAttributes.isValidValue(AttributeId, BagOf) (line
      114):
      s.isValid(value.valueType()) passes valueType() instead of value elements to isValid(Value).
  • Correct Behavior:
  Declare WithAttributes as a record:
    record WithAttributes(@Nonnull EntityTypeQualifier typeQualifier,
                          @Nonnull Map<AttributeId, AttributeSchema> attributes)
            implements AttributesSchema
  with an immutable map copy in its compact constructor, implementing attribute(AttributeId) via map lookup,
  and iterating elements v in isValidValue(AttributeId, BagOf) via s.isValid(v). Eliminate the non-
  functional Root stub or implement proper category delegation.

  #### Defect 2: EntitySchema.java Mutual Recursion and Truncated Expression

  • Citation: b9f114a3:xacml-core/src/main/java/org/xacml4j/v30/model/EntitySchema.java:50-61
  • Donor Code:
    default Optional<AttributeReferenceKey> eidRef(){
        return recordSchema().
    }

    default EntityTypeQualifier type() {
        return recordSchema().typeQualifier();
    }

    default AttributesSchema recordSchema(){
        return AttributesSchema.noAttributes(type());
    }

  • Analysis:
      1. Syntax Error / Truncated Line: Line 51 ends with a trailing dot (return recordSchema().), which
      fails compilation immediately.
      2. Infinite Mutual Recursion (StackOverflowError):
          • type() delegates to recordSchema().typeQualifier().
          • Default recordSchema() delegates to AttributesSchema.noAttributes(type()), which calls type().
          • Any invocation of type() or recordSchema() on an EntitySchema instance that relies on these
          defaults causes immediate infinite recursion and a StackOverflowError.

  • Correct Behavior:
  Make type() and recordSchema() abstract interface methods on EntitySchema without self-recursive default
  implementations. Provide an explicit eidRef() method returning Optional.empty() by default or delegating
  to a non-recursive schema lookup.

  #### Defect 3: Required-Domain Validation Gap

  • Citation: b9f114a3:xacml-core/src/main/java/org/xacml4j/v30/model/AttributesSchema.java:48-51 and
  b9f114a3:xacml-core/src/main/java/org/xacml4j/v30/model/ValueDomain.java:43-47
  • Donor Code:
    default boolean isValid(@Nonnull Record record){
        return record.attributes()
                .entrySet().stream().allMatch(e->isValidValue(e.getKey(), e.getValue()));
    }

  • Analysis:
      • AttributesSchema.isValid(Record) validates only the attributes present in record.attributes().
      • Although ValueDomain defines boolean required() (and ValueDomain.domain(type, required)),
      AttributesSchema.isValid(...) never verifies that mandatory attributes declared in the schema are
      present in the record.
      • Result: An empty record (attributes = Map.of()) passes validation against any schema, even if every
      attribute is marked required = true.
      • In addition, ValueDomain.java:33 imports com.sun.source.doctree.ValueTree;, an illegal internal
      com.sun compiler import.
  • Correct Behavior:
  AttributesSchema.isValid(Record record) must perform two-way validation:
      1. Every attribute present in record must be valid according to the schema's isValidValue(id, val).
      2. Every attribute defined in the schema with a required domain (domain.required() == true) must be
      present in record.attributes().

  #### Defect 4: Entity.equals / hashCode Broken Object Contract

  • Citation: b9f114a3:xacml-core/src/main/java/org/xacml4j/v30/types/Entity.java:133-145
  • Donor Code:
    @Override
    public boolean equals(Object o){
        return this == o || (o instanceof Entity entity &&
                Objects.equal(eid, entity.eid) &&
                (eid != null || Objects.equal(valueType, entity.valueType) &&
                Objects.equal(record, entity.record) &&
                Objects.equal(content, entity.content)));
    }

    @Override
    public int hashCode() {
        return Objects.hashCode(valueType, record, content, eid, parentId);
    }

  • Analysis:
      1. Contract Violation: When eid != null, equals() compares only eid (Objects.equal(eid, entity.eid)
      && (true || ...)), completely ignoring valueType, record, content, and parentId.
      2. Meanwhile, hashCode() hashes all five fields (valueType, record, content, eid, parentId).
      3. Consequently, two entities with identical eid but differing valueType, record, or parentId
      evaluate a.equals(b) == true, but produce different hash codes (a.hashCode() != b.hashCode()).
      4. This violates the fundamental contract of java.lang.Object, corrupting HashSet, HashMap, and cache
      lookups.
  • Correct Behavior:
  equals and hashCode must inspect the identical set of state fields. Per Design D8 and D11, entity
  equality must consistently compare valueType, eid, record, content, and parentId, and hashCode must hash
  the exact same fields.
