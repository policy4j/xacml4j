  ### B. Single Owner of xs:integer

  #### 1. Resolution & Ownership

  • Under XACML 3.0 §A.2 and XML Schema Part 2 §3.3.13, http://www.w3.org/2001/XMLSchema#integer represents
  the standard integer data-type.
  • In the donor branch, both Int64 and UInt32 declare @DataType(id = "http://www.w3.
  org/2001/XMLSchema#integer").
  • UInt32 cannot represent negative integers or numbers above 2³² - 1. Registering UInt32 as the owner or
  alias for xs:integer breaks standard XACML integer semantics.
  • Decision & Ownership:
      • Int64 (wrapping signed 64-bit long) is the sole owner of http://www.w3.org/2001/XMLSchema#integer
      (with alias "integer").
      • UInt32 and Int32 must NOT claim xs:integer or "integer". Their IDs must be non-standard internal
      identifiers (or omitted if unused).
      • The legacy IntegerVal in xacml-core must be replaced by Int64 (aliased or exposed via Primitives.
      Integer).

  ### C. Options for Overflow (Decision C3)

  XACML 3.0 §A.3.4 (Arithmetic Functions) does not mandate arbitrary precision for integers, but requires
  that operations unable to compute their mathematical result return Indeterminate with a processing-error
  status code (XACML 3.0 §7.3.3, §10.2.7).

  Two architectural options exist for addressing integer overflow:

   Dimension │ Option 1: Signed 64-bit long + Exact Arithmet… │ Option 2: Arbitrary Precision (BigInteger)
  ───────────┼────────────────────────────────────────────────┼────────────────────────────────────────────
   Mechanism │ Int64 holds primitive long. Arithmetic uses    │ Int64 holds java.math.BigInteger. Overflow
             │ Math.addExact, Math.multiplyExact,             │ is impossible; arithmetic produces
             │ Math.subtractExact. Overflows throw            │ mathematically exact values up to memory

   Conforman │ §7.3.3. When an integer exceeds implementation │ model in XML Schema §3.3.13.
   ce        │ limits, PDP yields Indeterminate (fail-        │
             │ closed).                                       │
   JDK 28 /  │ Primitive Value Candidate: Unboxed 64-bit flat │ Ineligible for flat memory layout:

  #### Recommendation

  Adopt Option 1 (Math.*Exact throwing ArithmeticException mapped to Indeterminate):

  1. It maintains fail-closed security semantics required by XACML.
  2. It satisfies Task 5.4's non-wrapping arithmetic requirement without ballooning allocation overhead.
  3. It directly supports the epic's core objective (Task 9.3: JDK 28 Project Valhalla primitive value
  classes).
