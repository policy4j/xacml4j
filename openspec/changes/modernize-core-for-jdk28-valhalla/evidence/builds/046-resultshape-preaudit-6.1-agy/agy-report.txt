  ### B. Interactions with Group 4 Fixes and Open Bugs

  1. Bug 4.8 (Variadic Higher-Order Functions, beads policy4j-the.4.8):
      • Worktree Status: Group 4 updated HigherOrderFunctions to support XACML 3.0 §A.3.12 variadic higher-
      order signatures for any-of, all-of, and any-of-any, allowing an arbitrary number of arguments where
      exactly one argument is a bag (at any parameter position).
      • Donor Conflict: Donor b9f114a3:HigherOrderFunctions.java:44-77 reverted to fixed 2-argument
      signatures (Value<?, ?> value, BagOf<?, ?> bag). Adopting the donor without preserving Group 4's
      SingleBagFunctionParametersValidator and AnyOfAnyFunctionParametersValidator breaks XACML 3.0 §A.3.12
      conformance. The worktree variadic shape must be retained.
  2. Bug 4.9 (AttributeSelector Singleton Context Node, beads policy4j-the.4.9):
      • Worktree Status: XACML 3.0 §7.3.7 requires that if ContextSelectorId is present, it MUST resolve to
      exactly one XML element node. 0 nodes or > 1 node must evaluate to Indeterminate (processing-error).
      The worktree enforces this via XmlContent and AttributeSelector.
      • Donor Conflict: Donor b9f114a3:AttributeSelector.java:58-75 and DefaultEvaluationContext perform
      unchecked node evaluation without validating singleton cardinality. requireExactlyOne() semantics
      must guard the context node resolution.
  3. Bug 4.35 (Quantifier Inversion in any-of-all, beads policy4j-the.4.35 / Grok NEW-1):
      • Worktree Status: Identified in Run 037 audit. XACML 3.0 §A.3.12 defines any-of-all(p, A, B) as: for
      each element of the second bag B, the predicate is true for at least one element of the first bag A
      (∀b ∈ B, ∃a ∈ A : p(a, b)).
      • Donor Conflict: Donor b9f114a3:HigherOrderFunctions.java:132-135 computes a.stream().anyMatch(v ->
      allOf(..., v, b)), which is ∃a ∈ A, ∀b ∈ B : p(a, b) (inverted quantifier order). The donor
      implementation fails on {1, 2} vs {1, 2} with integer-equal.
  4. Bug 4.38 (Numeric Conversions Swapped Annotations, beads policy4j-the.4.38 / Grok NEW-4):
      • Donor Conflict: b9f114a3:NumericConversionFunctions.java:48-57 swaps the return types: double-to-
      integer declares return type xs:double, and integer-to-double declares return type xs:integer. When
      Task 6.1 introduces strict ValueExprType matching, any policy invoking double-to-integer will
      statically expect xs:double, corrupting the AST type graph. The annotations must be fixed to match
      XACML 3.0 §A.3.6.
  5. Bug 4.43 (Syntax-Error Status Code Swallowing, beads policy4j-the.4.43 / Grok NEW-10):
      • Worktree Status: XACML 3.0 §A.3.9 requires string conversion functions (e.g. boolean-from-
      string("TRUE"), integer-from-string("abc")) to evaluate to Indeterminate with status code
      urn:oasis:names:tc:xacml:1.0:status:syntax-error.
      • Donor Conflict: Donor DefaultFunctionInvocation.java:128 catches all exceptions and wraps them in
      FunctionInvocationException, which hardcodes status code urn:oasis:names:tc:xacml:1.
      0:status:processing-error. The invocation wrapper must unwrap and propagate the status code from
      SyntaxException / EvaluationException.
  6. Condition Boolean Check (Adversarial Safety-Net Run 036):
      • Worktree Status: Conductor-confirmed requirement that Condition must enforce both:
          • Static: predicate.evaluatesTo().equals(BooleanVal.type()) (rejecting bags at load time).
          • Runtime: If dynamic evaluation yields an empty bag or multiple values, the result must be
          Indeterminate, not FALSE or first-element extraction.
      • Donor Conflict: Donor Condition.java:88 does .asSingle().orElse(false), which returns
      ConditionResult.FALSE on empty bags and uses findFirst() on multi-valued bags. requireExactlyOne() is
      required here.
