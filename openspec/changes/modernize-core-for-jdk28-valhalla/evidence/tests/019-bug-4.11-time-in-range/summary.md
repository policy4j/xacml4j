# policy4j-the.4.11: time-in-range identifier and interval

The XACML 3.0 Core specification Table 10.2.8 makes `urn:oasis:names:tc:xacml:2.0:function:time-in-range` the mandatory identifier. Its A.3.8 semantics define an inclusive interval whose upper endpoint is less than 24 hours after its lower endpoint, and specify time-zone handling. XACML 2.0's A.3.8 text and XACML 1.0's function definition use the `1.0` identifier for this function, so it is retained as a legacy alias. The official [XACML 3.0 Core](https://docs.oasis-open.org/xacml/3.0/xacml-3.0-core-spec-os-en.html), [XACML 2.0 Core](https://docs.oasis-open.org/xacml/2.0/access_control-xacml-2.0-core-spec-os.pdf), and [XACML 1.0 specification](https://www.oasis-open.org/committees/xacml/repository/cs-xacml-specification-01.pdf) documents are the identifier/semantics references.

Updated `NonNumericComparisonFunctions.timeInRange` to register the 2.0 identifier and the 1.0 alias, normalize times to UTC, and apply the context-handler time zone when the first argument omits a zone. Unzoned bounds inherit the first argument's effective zone. `ISO8601Time` now retains whether its input specified a zone so this behavior is possible. The interval remains inclusive and advances the end and candidate time to the next day as needed, so ranges can cross midnight.

`NonNumericComparisionFunctionTest` checks lookup and evaluation under both identifiers and evaluates the truth table: inclusive lower and upper boundaries, an interior value, values just outside either boundary, a wrapped `23:00`-`02:00` range, a value outside that wrapped range, offset normalization (`10:00+02:00` against `08:00Z`-`09:00Z`), the context default zone for an unzoned first value, and inheritance of that zone by unzoned bounds.

The scoped URI scan across core, PDP, XML, JSON, and conformance source/resources found no pre-existing test or fixture using either identifier; only this implementation previously registered the 1.0 URI. The legacy alias remains because it is defined by the earlier XACML specifications and preserves existing-policy compatibility.
