**2. Verdict: APPROVE WITH CHANGES**

The plan meets the goal (one JMH module; time and allocation per decision; any `PolicyRepository` by name from any jar; any corpus; decisions checked before measurement). Four major findings need artifact changes before implementation: a store lifecycle hook, exception handling in the decision check, the packaging that external stores compile against, and the test-visible surface for the parallel lanes. None requires a change to an existing module or the PDP API.

**3. Findings, most severe first**

**F1 (major) design.md D4 and D7; spec "Benchmark set". A store that owns resources has no release hook.**
- Problem: `PolicyStore` has `create` and `load` only. `PdpFixture.close()` "closes the repository when it is AutoCloseable" (design.md:161), but `PolicyRepository` does not extend `AutoCloseable` (checked in `xacml-pdp/src/main/java/org/xacml4j/v30/spi/repository/PolicyRepository.java:42-230`: no `close`), so the factory that knows what it opened never gets told to release it. `PolicyStoreLoadBenchmark` makes "a new repository plus `load`" per operation (design.md:204) and nothing disposes it. For a store with connections, files, or threads that is a leak per operation. `AbstractPolicyRepository` also allocates one `Executors.newSingleThreadExecutor()` per instance with no shutdown method (checked in `AbstractPolicyRepository.java:64-84`; the file has no shutdown); the thread starts only on a notice (checked `:167-193`), so the built-in stores leak an idle executor object per operation, not a thread.
- Why it matters: the packet's goal names "one that needs configuration or resources to close". Today such a store cannot be measured safely in the load benchmark and is released by luck in the others.
- Change: add to `PolicyStore` `default void close(PolicyRepository repository) throws Exception { if (repository instanceof AutoCloseable c) c.close(); }`. `PdpFixture.close()` calls `pdp.close()` then `store.close(repository)`. `PolicyStoreLoadBenchmark` keeps the repository it created in the thread state and calls `store.close` in `@TearDown(Level.Invocation)`; one load operation is long enough for invocation-level teardown. Spec "Policy store selection" gets: "The harness SHALL call the store's `close` for every repository it created, including those of the load benchmark", with a `PdpFixteTest`/`PolicyStoreLoadBenchmark` scenario using a test store that counts `create` and `close`. README (D12): the argument after the colon is the store's configuration handle (path or URL); multi-valued configuration goes in a file the store reads.

**F2 (major) design.md D5; spec "Decisions are checked before measurement", scenario "A store loses a policy". The check must catch exceptions, or the scenario ends in a NullPointerException instead of the specified IllegalStateException.**
- Problem: D5 collects "every request with a result count other than one or a decision other than the expected one" (design.md:177-181) and says nothing about `decide` throwing. With a test store built on `InMemoryPolicyRepository` that lacks a referenced policy set, `decide` on the `rsa2008` corpus throws: `InMemoryPolicyRepository.getPolicySets` passes `null` to `find`, which calls `Preconditions.checkNotNull` (checked `InMemoryPolicyRepository.java:97-103, 192-198`); the call comes from `AbstractPolicyRepository.getPolicySet` (`:112-122`) via `DefaultPolicyReferenceResolver.resolve` (`:123-127`) and `RootEvaluationContext.resolve` (`RootEvaluationContext.java:352`); `PolicySetIDReference.createContext` catches only `PolicyResolutionException` (`PolicySetIDReference.java:81-89`); the RSA root uses `urn:oasis:names:tc:xacml:1.0:policy-combining-algorithm:deny-overrides` (`XacmlPolicySet-01-top-level.xml:8-9`), registered as the class instance `LegacyDenyOverridesPolicyCombineAlgorithm` (`DefaultXacml30DecisionCombiningAlgorithms.java:70`) whose `combine` delegates to `doCombine` with no catch (`LegacyDenyOverridesPolicyCombineAlgorithm.java:49-55`; the generic `catch(Exception)` exists only in the annotated-method wrapper, `AnnotatedDecisionCombiningAlgorithmProviderFactory.java:123-132`, which the default provider does not use); `BaseCompositeDecisionRule.evaluate` (`:120-178`) and `DefaultPolicyDecisionPoint.decide`/`requestDecision` (`:92-108, 115-156`) have no enclosing catch. A store that instead returns `null`/empty follows the `PolicyResolutionException` path (`RootEvaluationContext.java:344-346, 357-359`) and yields Indeterminate, which XACML 1.0 deny-overrides turns into Deny; only requests whose expected decision is Permit then change.
- Why it matters: the spec promises an `IllegalStateException` that names each request; the fixture as designed would propagate the NPE from the first affected request, and a third-party store can throw from `get`, `load`, or a lookup in the same way.
- Change: D5: "an exception from `decide`, or from `get` in `open`, is recorded like a wrong decision (request id, expected, exception class and message) and all failures go into one `IllegalStateException`"; spec requirement text: "...when a request yields other than exactly one result, when deciding it throws, or when a decision differs...". Test note for 3.1: with a null-returning test store, drop a policy set that flips at least one expected Permit; with an `InMemoryPolicyRepository`-based store, expect the exception entries. Also add to the beads issue of task 1.2 that the unknown-id `NullPointerException` escapes `decide` for XACML 1.0/2.0 policy-combining algorithms (the engine's own null path at `PolicySetIDReference.java:83-85` gives Indeterminate).

**F3 (major) design.md D1, D2, D12; proposal "Impact". An external store cannot compile against the harness as planned, and the default shade configuration replaces the thin jar.**
- Problem: the harness API lives in `xacml-jmh`, which has `maven.deploy.skip=true` (design.md:73-76). An external store must compile against `org.xacml4j.jmh.harness.PolicyStore`. "By default, the plugin replaces the project's main artifact with the shaded artifact" (maven.apache.org, maven-shade-plugin `examples/attached-artifact.html`, via Context7 2026-10-26), so `mvn install` would install the fat jar (xacml-core, xacml-pdp, Guava, log4j inside) under the `xacml-jmh` coordinates, the wrong compile dependency for an external project that has its own `xacml-pdp`. The default also writes `dependency-reduced-pom.xml` into the module directory, an untracked file that the gate's `git status` check does not cover. The shade mojo documents: `finalName` "If this is set to something different than `<build><finalName>`, no file replacement will be performed", and `outputFile` "the created archive will neither replace the project's main artifact nor will it be attached ... causes the parameters finalName, shadedArtifactAttached, shadedClassifierName and createDependencyReducedPom to be ignored" (maven.apache.org `shade-mojo.html`, via Tavily 2026-10-26). `.gitignore` lists each module's `target` directory by name and has no `/xacml-jmh/target` entry (checked `.gitignore:5-59`).
- Why it matters: the goal is "stores that live outside this repository" (proposal.md:8-10); without a thin artifact and a documented path there is no supported way to compile one.
- Change: D2: configure the shade execution with `<outputFile>${project.build.directory}/benchmarks.jar</outputFile>` (keeps `xacml-jmh-<version>.jar` thin, writes no dependency-reduced POM). D12 and README: an external store depends on `org.xacml4j:xacml-jmh:<version>` (provided scope) plus `xacml-pdp`, obtained with `mvn install` of this reactor because the module is not deployed; the run command stays `java -cp benchmarks.jar:<jar> org.openjdk.jmh.Main`. Task 2.2 adds `/xacml-jmh/target` to `.gitignore`; proposal "Impact" and "Migration and Rollback" list `.gitignore`.

**F4 (major) design.md D4, D8, D10; tasks 3.1 to 3.5. The parallel test lane needs more fixed surface than D4 gives.**

- Change: add D13 "Test-visible surface": `public SnapshotPolicyRepository(String id, FunctionProvider functions, DecisionCombiningAlgorithmProvider algorithms)`, mirroring `InMemoryPolicyRepository.java:64-72`; each benchmark class in `org.xacml4j.jmh.pdp` is itself the `@State(Scope.Benchmark)` with public `@Param` fields `store`, `corpus` (and `request` on `PdpDecideBenchmark`), `public void setUp() throws Exception` under `@Setup(Level.Trial)`, `public void tearDown()` under `@TearDown(Level.Trial)`, and a nested `@State(Scope.Thread) public static class Cursor`. `SyntheticCorpusTest` and `DirectoryCorpusTest` go through `PolicyCorpora.load(...)` only, so the corpus lane keeps its internals private.

**F5 (minor) design.md D7 and D10. Lookup comparability and the store-blind decide.**
- Problem: `InMemoryPolicyRepository` overrides `get(id, Version)` with a direct map lookup (checked `InMemoryPolicyRepository.java:106-114`), while the inherited `AbstractPolicyRepository.get` builds a `VersionMatch`, filters, and takes `Collections.max` (checked `AbstractPolicyRepository.java:96-105, 204-210`). D10 does not say the snapshot store overrides `get`; if it does not, `getByIdAndVersion` compares two code paths, not two stores. Separately, the resolver cache has no maximum size: the one-argument constructor passes 1024 as `size` (checked `DefaultPolicyReferenceResolver.java:55-58`), but the three-argument constructor uses it nowhere; the caches are built with `initialCapacity(1024)` only (checked `:60-77`). So after the D5 check, `decide` never calls the store at any corpus size, including `synthetic:100000`.
- Change: D10 states that `get(id, Version)`, `getPolicy`, and `getPolicySet` are direct `NavigableMap` lookups (`get`, `lastEntry`), with the "same answers" requirement unchanged. D7 and the README say in one sentence that `PdpDecideBenchmark` is store-independent by construction because the reference cache is unbounded; the baseline `summary.md` repeats it. Record the unused `size` argument in the same beads note as the NPE (not fixed here).

**5. Residual risks**

- Not run by this lane: `openspec validate --strict`, any Maven build, the reactor test count (8,009/0/18 is not checked).
- An unknown id crashes `decide` with the in-memory store (F2 chain), so the lookup benchmark must not include miss cases until the beads issue is fixed.
- `BenchmarkSmokeTest` runs JMH in process on every reactor build (three benchmarks, two stores, two corpora, plus a GC-profiler run); keep the 100 ms iterations or build time grows.
- `loadParsed` and `importXml` include repository construction, which for `AbstractPolicyRepository` subclasses allocates an executor per operation (JDK 21 wraps it with a Cleaner-backed auto-shutdown service, not checked in JDK source); say so in the baseline summary so it is not read as store cost.
- Multi-thread runs: the shared `Random` (F8) and the `MetricRegistry` counters (`DefaultPolicyDecisionPoint.java:85-88, 158-168`) scale differently from evaluation.
