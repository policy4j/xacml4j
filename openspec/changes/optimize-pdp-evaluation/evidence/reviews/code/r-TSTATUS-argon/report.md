## Verification of Check Points

### 1. XACML 3.0 §§7.11–7.14, §7.19.2, §7.19.3, and Annex C (`SUPPORTED`)
- **Normative specification**:
  - **XACML 3.0 Plus Errata 01 §7.11 (Table 4)**: A rule whose target is `Indeterminate`, or whose target matches and whose condition is `Indeterminate`, evaluates to `Indeterminate{P}` (`Effect="Permit"`) or `Indeterminate{D}` (`Effect="Deny"`). A rule with a `No-match` target or `False` condition evaluates to `NotApplicable`.
  - **§§7.12–7.14 (Tables 5–7) and Annex C (C.1–C.13)**: Combining algorithms combine child decisions over `Permit`, `Deny`, `NotApplicable`, `Indeterminate{D}`, `Indeterminate{P}`, and `Indeterminate{DP}`. Neither Tables 4–7 nor the normative pseudocode in Annex C define combining or precedence rules for `<Status>` across multiple errors; §5.48 makes `<Status>` optional in `<Result>`.
  - **§7.19.2 (Syntax and type errors)**: *"If a policy that contains invalid syntax is evaluated by the XACML PDP at the time a decision request is received, then the result of that policy SHALL be 'Indeterminate' with a StatusCode value of 'urn:oasis:names:tc:xacml:1.0:status:syntax-error'."*
  - **§7.19.3 (Missing attributes)**: *"The absence of matching attributes in the request context for any of the attribute designators attribute or selectors that are found in the policy will result in an enclosing `<AllOf>` element to return a value of 'Indeterminate', if the designator or selector has the MustBePresent XML attribute set to true, as described in Sections 5.29 and 5.30 and may result in a `<Decision>` element containing the 'Indeterminate' value. If, in this case a status code is supplied, then the value 'urn:oasis:names:tc:xacml:1.0:status:missing-attribute' SHALL be used..."*
- **When a rule's `Indeterminate` is combined away into a determinate decision (e.g., `deny-overrides` with another rule that denies)**:
  - In [`DenyOverrides.doCombine`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/impl/DenyOverrides.java`), a sibling rule returning `Decision.DENY` produces a combined decision of `Decision.DENY` (or `Decision.PERMIT` when an `Indeterminate{P}` rule is combined with a `Permit` rule and no `Indeterminate{D}`).
  - In [`DefaultPolicyDecisionPoint.createResult`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultPolicyDecisionPoint.java`), `context.getEvaluationStatus()` is read **only** when `decision.isIndeterminate()` is `true` (lines `320-325`). Every `Permit`, `Deny`, or `NotApplicable` result is built via [`Result.of`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/Result.java`) with [`Result.OK`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/Result.java`) (`urn:oasis:names:tc:xacml:1.0:status:ok`). No status from a failed rule target leaks into any determinate `Result`.
- **When the final decision is `Indeterminate` from another rule/policy, and comparison with `Condition` today**:
  - Because [`DescendantEvaluationContext.setEvaluationStatus(Status)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) propagates immediately up to [`RootEvaluationContext.setEvaluationStatus(Status)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) (last-write-wins outside extended-Indeterminate passes), a failing [`Match`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Match.java`) in a rule target writes `e.getStatus()` to `root.evaluationStatus` at the point the match fails.
  - This matches [`Condition.evaluate`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Condition.java`) (`context.setEvaluationStatus(e.getStatus())`) and policy/policy-set targets (`rule == null` in [`Match.match`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Match.java`), delegated by [`DescendantEvaluationContext.setEvaluationStatus(DecisionRule, Status)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`)).
  - Furthermore, even before `FIX-TSTATUS`, a failing rule target **already** wrote to `root.evaluationStatus`:
    1. [`AttributeDesignator.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeDesignator.java`) and [`AttributeSelector.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeSelector.java`) called `context.setEvaluationStatusIfAbsent(...)` on `ruleContext` before throwing, which wrote to `root.evaluationStatus`.
    2. Whenever a rule target returned `MatchResult.INDETERMINATE`, [`Rule.evaluateRule`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`) called `context.setEvaluationStatusIfAbsent(() -> Status.processingError().build())` on `ruleContext`, which wrote a bare `processing-error` to `root.evaluationStatus` whenever `Match.match` had not set `ruleContext.evaluationStatus`.
  - Thus, `FIX-TSTATUS` replaces the bogus fallback `processing-error` write in `Rule.evaluateRule` with the actual `e.getStatus()` (`syntax-error`, `missing-attribute`, or `processing-error` with message).
  - *Pre-existing architectural note (outside `FIX-TSTATUS` scope)*: Because the engine pushes `evaluationStatus` to `parent` and `root` eagerly on each failure rather than staging status per `<AllOf>` / `<AnyOf>` / `Rule` / `Policy`, an absorbed `Indeterminate` inside a `<MatchAllOf>` that later resolves to `NOMATCH` ([`MatchAllOf.java:67-78`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/MatchAllOf.java`)), inside a `<MatchAnyOf>` that later resolves to `MATCH` ([`MatchAnyOf.java:59-69`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/MatchAnyOf.java`)), or inside a later composite child whose own result becomes `Permit` or `NotApplicable` while an earlier sibling composite was `Indeterminate{D}`, can still overwrite `root.evaluationStatus`. That is the same eager-propagation model used by `Condition`, `AttributeDesignator`, `AttributeSelector`, and policy targets, and is allowed by XACML 3.0 Annex C.

### 2. The Extended-Indeterminate Pass (`SUPPORTED`)
- When a `Policy` or `PolicySet` target, condition, or obligation/advice fails, its context sets `this.evaluationStatus` before [`BaseCompositeDecisionRule.extendedIndeterminatePass`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`) calls `createExtIndeterminateEvalContext()`.
- On the pass boundary context (`pass`), `startsPass()` (`isExtendedIndeterminateEval() && !parent.isExtendedIndeterminateEval()`, [`DescendantEvaluationContext.java:122-124`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`)) is `true` and `parent.getEvaluationStatus().isPresent()` is `true`.
- When a rule target inside the pass fails and [`Match.match`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Match.java`) calls `context.setEvaluationStatus(e.getStatus())`, propagation walks up `ruleContext` -> child `policyContext` -> `pass` and stops at [`DescendantEvaluationContext.java:107-111`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`), preserving the status of the failure that started the pass on `parent` and `root`.

### 3. `setEvaluationStatusIfAbsent` in `Rule.evaluateRule` (`SUPPORTED`)
- In [`DescendantEvaluationContext.setEvaluationStatusIfAbsent`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`), `if (evaluationStatus == null)` checks the private per-context field [`DescendantEvaluationContext.evaluationStatus`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) on the current `RuleEvaluationContext`, **not** `parent.evaluationStatus` or `root.evaluationStatus`.
- Because [`Rule.createContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`) creates a fresh `RuleEvaluationContext` for each rule evaluation (`this == context.getCurrentRule()`), a later failing rule always starts with `ruleContext.evaluationStatus == null`.
- Therefore, an earlier status from another rule never causes `setEvaluationStatusIfAbsent` on a later rule's `RuleEvaluationContext` to skip setting the later rule's status.
- Within a single rule's target evaluation, [`Match.match`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Match.java`) calls `context.setEvaluationStatus(e.getStatus())` (unconditional), overwriting the terse `Status.missingAttribute(key)` that [`AttributeDesignator.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeDesignator.java`) or [`AttributeSelector.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeSelector.java`) wrote via `setEvaluationStatusIfAbsent`, and then [`Rule.evaluateRule`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`) sees `ruleContext.evaluationStatus != null` and does not overwrite `e.getStatus()` with `Status.processingError().build()`.
