### 2. Verification of the Unchanged Walks (`SUPPORTED`)

1. **[`PolicyIDReference.isReferenceCyclic`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicyIDReference.java`) and [`PolicySetIDReference.isReferenceCyclic`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicySetIDReference.java`)**:
   - At each step `c`, `isReferenceCyclic` calls `c.getCurrent*IDReference()`, which walks `DescendantEvaluationContext.parent` via [`DescendantEvaluationContext.getCurrentPolicyIDReference`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) / [`getCurrentPolicySetIDReference`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`).
   - When `c` is `StagedResponses(delegate)`, `c.getCurrent*IDReference()` immediately inspects `delegate`. Stepping `c` to `c.getParentContext()` (`delegate.getParentContext()`) skips only `delegate`, which was just inspected. (In an extended Indeterminate pass where `StagedResponses` wraps `PolicySetPassEvaluationContext(delegate)`, `c.getParentContext()` is `delegate`, so nothing is skipped.)
2. **[`BaseCompositeDecisionRule.isEnclosed`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`)**:
   - `isEnclosed(context)` advances `c = c.getParentContext()` before testing `c instanceof PolicySet.PolicySetDescendantEvaluationContext`.
   - By induction on the `PolicySet` nesting depth, the outermost `PolicySet` has no enclosing `PolicySetDescendantEvaluationContext`, so `isEnclosed(outerPolicySetContext)` is `false` and [`BaseCompositeDecisionRule`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`) never wraps `outerPolicySetContext` in `StagedResponses`. Every inner `getParentContext()` walk therefore still lands on `outerPolicySetContext` (which is a `PolicySetDescendantEvaluationContext`) and returns `true`. Conversely, when `isEnclosed` is called with `context = StagedResponses(outerPolicySetContext)` (if a custom algorithm invoked a second composite rule on `staged`), the initial `c = context.getParentContext()` skips `outerPolicySetContext` so the outer policy set does not treat itself as enclosing itself. Opus's reasoning holds.
3. **Observers and `getCurrent*` queries**:
   - `DecisionObservation` callbacks receive the current context and do not walk parents.
   - All `getCurrent*` methods on [`DescendantEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) and `isStaging` / `closeStaging` on `RootEvaluationContext` already walk `DescendantEvaluationContext.parent`.

### 3. Residual Risk for Foreign Contexts Overriding `getParentContext()` (`SUPPORTED`)

- `Rule.RuleEvaluationContext` is the only `public` subclass of `DescendantEvaluationContext` (all other subclasses are package-private).
- [`DescendantEvaluationContext.isOwn`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) checks `c.getClass().getPackageName().equals(OWN_PACKAGE)` (`"org.xacml4j.v30.policy"`). An external subclass of `Rule.RuleEvaluationContext` has `isOwn(c) == false`, so `topOf(context)` stops at that subclass and the second loop of `isPolicyCyclic` / `isPolicySetCyclic` calls its overridden `getParentContext()`.
- Only `isEvaluating` and `setEvaluating` walk `d.getParent()` past an external `Rule.RuleEvaluationContext` subclass (`Rule` never creates policy references, so this only occurs if user code manually passes a custom `RuleEvaluationContext` into a `PolicyIDReference` or `PolicySetIDReference`), and even then it only checks whether an ancestor reference context for `this` reference is currently active. The residual risk is negligible.

### 2. Findings on `Cycle AS`

#### `P2-1` — Custom `FunctionSpec` predicates do not keep variadic dispatch in binary `any-of`, `all-of`, `all-of-any`, and `any-of-all`, while `HigherOrderFunctions` duplicates `usesBuiltInInvocation` guards

- **Location**:
  - [`DecidingOperands.java:204`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/DecidingOperands.java`)

  - [`FunctionSpecBuilder.java:291-299`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`)
  - [`HigherOrderVariadicFunctionsTest.java:228-243`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/function/impl/HigherOrderVariadicFunctionsTest.java`)
- **Failure**:
  1. Before `Cycle AS` (and still in `allOfAll`), higher-order functions invoked a binary predicate through `FunctionReference` using the variadic `spec.invoke(context, Expression...)` overload unless the predicate was a trusted built-in. In [`DecidingOperands.firstDeciding`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/DecidingOperands.java`) — used by `anyOf`, `anyOfPair`, `allOf`, `allOfPair`, `allOfAny` (via `allAny`), and `anyOfAll` (via `allAny`) — the predicate is called via `predicate.invoke(context, value, argument)`, which unconditionally calls `spec.invoke(context, arg0, arg1)` even when `spec` is a custom `FunctionSpec` (`!usesBuiltInInvocation(spec)`). Consequently, for the custom `FunctionSpec` in [`HigherOrderVariadicFunctionsTest.customPredicateKeepsItsVariadicInvocation`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/function/impl/HigherOrderVariadicFunctionsTest.java`) (where `invoke(context, Expression...)` returns `TRUE` and `invoke(context, Expression, Expression)` returns `FALSE`), `"any-of-any"`, `"all-of-all"`, and `"map"` call the variadic overload (`TRUE`), whereas binary `"any-of"`, `"all-of"`, `"all-of-any"`, and `"any-of-all"` call the 2-argument default method (`FALSE`).
  2. Conversely, `anyOfSingle`, `allOfSingle`, `anyOfAnyPair`, `anyOfAnySingle`, `mapPair`, and `mapSingle` check `if (ref != null && !ref.usesBuiltInInvocation()) return ...(context, ref, new Value[]{...});` at the top and then call `ref.invokeVariadicSingle` / `ref.invokeVariadicPair`, which check `FunctionSpecBuilder.usesBuiltInInvocation(spec)` a second time. Because `requireValidArguments` rejects `ref == null`, `ref.usesBuiltInInvocation()` is always `true` when `invokeVariadicSingle` is reached, making the non-built-in fallback branch `return spec.invoke(context, new Expression[]{argument});` in [`FunctionSpecBuilder.invokeVariadicSingle`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`) dead code and forcing custom `@XacmlFunctionProvider` predicates onto the outer `Value[]` fallback.
- **Fix**:
  1. Route [`FunctionReference.invoke(EvaluationContext, Expression, Expression)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/FunctionReference.java`) through `FunctionSpecBuilder.invokeVariadicPair(getSpec(context), context, arg0, arg1)` (so `spec.invoke(context, arg0, arg1)` is used when `usesBuiltInInvocation(spec)` is true, and `spec.invoke(context, new Expression[]{arg0, arg1})` when false).
  2. Rename `FunctionReference.invokeVariadicSingle(EvaluationContext, Expression)` to the matching 1-argument overload `FunctionReference.invoke(EvaluationContext, Expression)` and remove `FunctionReference.invokeVariadicPair` and `FunctionReference.usesBuiltInInvocation()`, along with the redundant `if (ref != null && !ref.usesBuiltInInvocation())` early returns in `HigherOrderFunctions`.
  3. Expand [`HigherOrderVariadicFunctionsTest.customPredicateKeepsItsVariadicInvocation`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/function/impl/HigherOrderVariadicFunctionsTest.java`) to assert `"any-of"`, `"all-of"`, `"all-of-any"`, `"any-of-all"`, and `"all-of-all"` in addition to `"any-of-any"` and `"map"`.
