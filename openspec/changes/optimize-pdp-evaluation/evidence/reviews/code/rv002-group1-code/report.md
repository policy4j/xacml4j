## Residual Risks

1. **High-core-count cache-line sharing on `correlationSequence`**: One `AtomicLong` per PDP is shared by all threads calling `decide` on that PDP instance. `incrementAndGet()` (`getAndAddLong`) eliminates the 4 global `Random` CAS loops and per-individual-decision contention; if future multi-threaded profiling shows `correlationSequence` cache-line traffic, a thread-local prefix/counter can be evaluated in a later group.
2. **Custom multi-threaded `RequestContextHandler` implementations**: `NumberedDecisions.decisions` uses a plain `int` because all built-in handlers (`MultipleResourcesHandler` and `Budget`) evaluate expanded requests sequentially on the request thread (`design.md:14-16`). A third-party `RequestContextHandler` that dispatches `context.requestDecision` across worker threads for a single `decide` call is unsupported by both `Budget` and `NumberedDecisions`.
