## 2. The Visible Difference: `getParentContext()` Depth in Unobserved Decisions

In an unobserved decision rooted at `RootEvaluationContext`, calling `getParentContext()` on the context of a referenced `Policy` or `PolicySet` now returns the enclosing `PolicySet`'s context (or `RootEvaluationContext`) directly, rather than an intermediate `Policy[Set]IDReferenceEvaluationContext`.

A repository-wide search (`rtk rg`) across `xacml-core`, `xacml-pdp`, `xacml-test`, and `xacml-jmh` (152 matches in 15 files) confirms that nothing breaks (`SUPPORTED`):
1. **Engine walks:** Only three methods in production code call `getParentContext()`:
   - [`BaseCompositeDecisionRule.isEnclosed`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`), which checks `c instanceof PolicySet.PolicySetDescendantEvaluationContext` (satisfied by `ReferencedPolicySetContext`);
   - [`PolicyIDReference.isReferenceCyclic`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicyIDReference.java`) and [`PolicySetIDReference.isReferenceCyclic`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicySetIDReference.java`), which check `context.getCurrentPolicy[Set]IDReference()` (answered by `ReferencedPolicy[Set]Context`);
   - [`EvaluationContext.getReferencedCompositeDecisionRules`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/EvaluationContext.java`), an unused default method on `EvaluationContext`.
2. **Public contracts:** [`EvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/EvaluationContext.java`) exposes semantic accessors (`getCurrentRule()`, `getCurrentPolicy()`, `getCurrentPolicySet()`, `getCurrentPolicyIDReference()`, `getCurrentPolicySetIDReference()`, `getCurrentDecisionRule()`) and does not specify that a reference and its target must occupy two separate nodes in `getParentContext()`. Both `PolicyIDReferenceEvaluationContext` and `PolicyDescendantEvaluationContext` (and their `PolicySet` counterparts) are package-private classes.
3. **Tests:** [`PolicyIDReferenceTest.testCreatePolicyIDReferenceEvaluatonConntext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/PolicyIDReferenceTest.java`) asserts a two-hop `getParentContext().getParentContext()` on a mock `EvaluationContext`, which is a foreign root (`isUnobserved(context) == false`) and continues to use the two-context path. [`ContextChainQueryCharacterizationTest.nearestLevelAnswersQueriesAboutWhatItEvaluates`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/ContextChainQueryCharacterizationTest.java`) runs against an unobserved `RootEvaluationContext` and verifies all level queries across `outer -> innerRef -> inner -> policyRef -> policy -> rule`.

## 5. The Cyclic-Reference Finding vs. OASIS XACML 3.0 Plus Errata 01

### Exact Normative Text (Fetched via `tavily_extract`)

From **OASIS eXtensible Access Control Markup Language (XACML) Version 3.0 Plus Errata 01**, OASIS Standard, 12 July 2017 (`https://docs.oasis-open.org/xacml/3.0/errata01/os/xacml-3.0-core-spec-errata01-os-complete.html`):

- **Section 5.10 (`Element <PolicySetIdReference>`) & Section 5.11 (`Element <PolicyIdReference>`):**
  > "**5.10 Element `<PolicySetIdReference>`**
  > The `<PolicySetIdReference>` element SHALL be used to reference a `<PolicySet>` element by id. If `<PolicySetIdReference>` is a URL, then it MAY be resolvable to the `<PolicySet>` element. However, the mechanism for resolving a policy set reference to the corresponding policy set is outside the scope of this specification."
  >
  > "**5.11 Element `<PolicyIdReference>`**
  > The `<PolicyIdReference>` element SHALL be used to reference a `<Policy>` element by id. If `<PolicyIdReference>` is a URL, then it MAY be resolvable to the `<Policy>` element. However, the mechanism for resolving a policy reference to the corresponding policy is outside the scope of this specification.
  > Element `<PolicyIdReference>` is of `xacml:IdReferenceType` complex type (see Section 5.10) ."

- **Section 7.15 (`PolicySetIdReference and PolicyIdReference evaluation`):**
  > "**7.15 PolicySetIdReference and PolicyIdReference evaluation**
  > A policy set id reference or a policy id reference is evaluated by resolving the reference and evaluating the referenced policy set or policy.
  > If resolving the reference fails, the reference evaluates to Indeterminate with status code `urn:oasis:names:tc:xacml:1.0:status:processing-error`.
  > A policy set id reference or a policy id reference containing circular references is invalid. The PDP MUST detect circular references either at policy loading time or during runtime evaluation. If the PDP detects a circular reference during runtime the reference evaluates to Indeterminate with status code `urn:oasis:names:tc:xacml:1.0:status:processing-error`."

### Assessment

**Yes — throwing an uncaught `IllegalStateException` (or `IllegalArgumentException` in `PolicyIDReference`) during `pdp.decide(...)` violates XACML 3.0 (Errata 01) §7.15.**

1. Under §7.15, a conforming PDP MUST detect circular references either:
   - **at policy loading time** (rejecting the circular policy set), or
   - **during runtime evaluation**, in which case **"the reference evaluates to Indeterminate with status code `urn:oasis:names:tc:xacml:1.0:status:processing-error`"** (and participates in policy-combining algorithm evaluation as `Indeterminate` / `Indeterminate{DP}`).
2. In `xacml4j`, `InMemoryPolicyRepository` does not reject circular references at load time. Instead, [`PolicySetIDReference.isReferenceCyclic`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicySetIDReference.java`) detects the cycle at runtime inside `createContext(context)` and throws `new IllegalStateException("Cyclic reference detected")` (while [`PolicyIDReference.checkCanEnter`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicyIDReference.java`) throws `IllegalArgumentException`). Because combining algorithms call `child.createContext(context)` without catching runtime exceptions, the exception escapes `DefaultPolicyDecisionPoint.decide(...)` instead of evaluating the cyclic reference to `Decision.INDETERMINATE` (or `Indeterminate{DP}`) with `Status.processingError()`.
3. This is a pre-existing engine defect (not introduced by Cycle AP) and should be tracked as a separate spec-compliance issue.
