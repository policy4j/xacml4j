#### 2. `DefaultPolicyDecisionPoint.getResolvedAttributes` — Direct `BagOfValues` Iteration
- **Elimination of `ImmutableMultiset` materialization ([`DefaultPolicyDecisionPoint.java:338-342`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultPolicyDecisionPoint.java`)):** Passing `.values(v)` instead of `.values(v.values())` at line 341 invokes [`Attribute.Builder.values(Iterable<Value<?>>)`](`xacml-core/src/main/java/org/xacml4j/v30/Attribute.java`) directly on `BagOfValues` (which implements `Iterable<Value<?>>` via [`BagOfValues.iterator()`](`xacml-core/src/main/java/org/xacml4j/v30/BagOfValues.java`)), bypassing the lazy `ImmutableMultiset<Value<?>>` allocation in [`BagOfValues.values()`](`xacml-core/src/main/java/org/xacml4j/v30/BagOfValues.java`).
- **Identical elements, grouped order, duplicates, `NaN`, signed zero, and issuer ([`BagStorages.java:108-376`](`xacml-core/src/main/java/org/xacml4j/v30/BagStorages.java`)):**
  - `BagOfValues.values()` populated its `ImmutableMultiset` by iterating `i = 0 .. storage.distinctSize() - 1` and adding `storage.distinctValueAt(i)` with multiplicity `storage.distinctCountAt(i)`.
  - `BagOfValues.iterator()` delegates to `storage.iterator()`, which iterates `index = 0 .. size() - 1` and yields `storage.valueAt(index)`.
  - Across all `BagStorages` implementations (`Empty`, `Single`, `Values`, `Integers`, `Doubles`, `Booleans`), `Builder.build()` groups equal values by first-appearance order into contiguous slices `offsets[i] .. offsets[i + 1]`. Because `DoubleVal.equals` uses `Double.equals` (`doubleToLongBits`), `-0.0` and `0.0` occupy separate groups and `Double.NaN` values coalesce into a single group. Consequently, `storage.iterator()` yields the exact same sequence of `Value<?>` elements—same grouped first-appearance order, duplicate counts, `NaN` values, and `-0.0` vs. `0.0` distinction—as `v.values().iterator()`, while preserving `k.getAttributeId()` and `k.getIssuer()`.
