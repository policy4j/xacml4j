**RV209-ASTRA-1 — P2: category-bearing aliases make the positive AttributeIndex memo unbounded again.**

Location: `xacml-core/src/main/java/org/xacml4j/v30/AttributeIndex.java:351`, particularly the unconditional positive alias insertion at :361. The strong map is declared at :75 and created at :367.

Trigger: retain one Entity containing one string attribute with ID `a`. Repeatedly call its public `resolve(AttributeDesignatorKey)` with that same ID, type and issuer, but a different valid category URI on each key. `C/types/Entity.java:231` delegates without a category check because an Entity has no category of its own. `C/AttributeDesignatorKey.java:98` includes category in equality (:107); `C/CategoryId.java:152` accepts distinct valid URIs. The category-free lookup resolves the same positive bag each time, after which :361 retains each distinct full key.

Reachable impact: the Entity's live AttributeIndex retains one additional key/category and concurrent-map entry per successful distinct-category lookup. This growth is unrelated to the number of stored attributes and persists as long as the Entity does. A reusable Entity queried across changing category keys can accumulate memory without bound. The normal Category wrapper's category check does not constrain this public Entity API. This is a retention failure, not a claimed change to the returned bag or a measured throughput regression.

History: r-FABLE2-sol raised this structural-bound problem; FIX-30b changed the memo and r-FABLE3-sol closed it. Cycle AM then added the full-designator alias path for allocation-free repeat lookup (`Change/tasks.md:295`). r-AM-argon's matrix item 3 approves a map “bounded by the stored attributes and the designators that match them,” but arbitrarily many category-distinct designators match this same Entity. That later approval misses the original counterexample.

Minimal correction: retain only the category-free canonical lookup entries, or put a fixed independent bound on the full-key alias cache. Preserve category-independent Entity resolution, concurrent winner selection and canonical Optional/bag identity; do not reject legitimate keys to hide the retention issue.

Regression to add in an authorized implementation/probe lane: query one fixed Entity through many category-distinct positive keys and assert identical resolved contents and canonical bag identity; demonstrate that retained aliases stay within the chosen fixed bound rather than growing with query count.
