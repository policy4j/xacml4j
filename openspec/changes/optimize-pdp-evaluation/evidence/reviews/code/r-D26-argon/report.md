### [P2-1] `ParallelAttributeResolverTest` does not exercise `PreparedContext` confinement, cacheable complete-vs-partial `AttributeSet` caching, or `maxConcurrentResolutions`
- **File:line**: [`ParallelAttributeResolverTest.java:51-175`](`xacml-pdp/src/test/java/org/xacml4j/v30/spi/pip/ParallelAttributeResolverTest.java`) (covering [`AttributeResolverDescriptor.java:306, 339-363`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeResolverDescriptor.java`), [`DefaultPolicyInformationPoint.java:82-90`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`), and [`StructuredResolverRunner.java:78-92`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/StructuredResolverRunner.java`)).
- **Issue**: The four existing tests in `ParallelAttributeResolverTest` are clean and focused, but all use `.noCache()` (`:109, 127, 157`) and none exercise three core D26 invariants:
  1. **`PreparedContext` confinement and pre-resolved context keys**: no test verifies that `c.getEvaluationContext()` inside a parallel attribute function throws `IllegalStateException` (mapped to `processing-error` by the PIP), or that a declared `.contextRef(key)` is resolved on the deciding thread and readable from worker threads via `c.resolveContextRef(key)`.
  2. **Only complete `AttributeSet`s are cached**: no test uses `.cache(ttl)` with a `PolicyInformationPointCacheProvider` to verify that (a) when all attribute functions succeed, `putAttributes` is called once and sibling lookups hit the cache, whereas (b) when one attribute function succeeds and another fails (`!value.get().isComplete()`), the succeeding attribute is returned but `putAttributes` is **not** called.
  3. **Concurrency limit (`maxConcurrentResolutions`) and rejected execution**: no test exercises `maxConcurrentResolutions(int)` or a rejecting `resolverExecutor`.
- **Fix**: Add focused tests in [`ParallelAttributeResolverTest.java`](`xacml-pdp/src/test/java/org/xacml4j/v30/spi/pip/ParallelAttributeResolverTest.java`) for:
  1. `preparedContextReadsResolvedKeysAndForbidsEvaluationContext()`: configure `.contextRef(USER_ID)` on a parallel resolver; verify `c.resolveContextRef(USER_ID)` returns the user bag on the worker thread and `c.getEvaluationContext()` fails resolution with `STATUS_PROCESSING_ERROR`.
  2. `onlyCompleteAttributeSetsAreCached()`: with a mocked or in-memory `PolicyInformationPointCacheProvider` and `.cache(60)`, verify `cache.putAttributes` is called when both `role` and `department` succeed, and never called when `department` throws while `role` succeeds.
  3. `maxConcurrentResolutionsBoundsInFlightTasks()`: with `maxConcurrentResolutions(1)` and an `AtomicInteger` active counter across two attribute functions, assert max observed concurrency is `1`.

### [P3-1] `PreparedContext` eagerly calls `context.getCurrentDateTime()` (allocating `ZonedDateTime.now(clock)`) on every parallel resolver call, and `resolve` builds an `AttributeSet` before checking whether all attributes returned `null`
- **File:line**: [`AttributeResolverDescriptor.java:170, 176, 197-198, 301, 307-308, 318`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeResolverDescriptor.java`).
- **Issue**:
  1. [`PreparedContext(ResolverContext)`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeResolverDescriptor.java`) unconditionally calls `this.currentDateTime = context.getCurrentDateTime()` (`:307`). On `EvaluationContext`'s default implementation ([`EvaluationContext.java:137-139`](`xacml-core/src/main/java/org/xacml4j/v30/EvaluationContext.java`)), `getCurrentDateTime()` invokes `ZonedDateTime.now(getClock())`, reading the system clock and allocating a `ZonedDateTime` on every parallel resolver invocation even though no parallel attribute resolver reads `getCurrentDateTime()`. It also causes an extra interaction on mocked `EvaluationContext`s compared to synchronous descriptors (which only call `context.getClock()`, [`DefaultPolicyInformationPointTest.java:209-211`](`xacml-pdp/src/test/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPointTest.java`)).
  2. When all attribute functions of a parallel descriptor return `null` (or when `context` is an unstubbed mock whose `getClock()` is `null`, as in [`DefaultPolicyInformationPointTest.java:336-348, 670-675`](`xacml-pdp/src/test/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPointTest.java`)), synchronous descriptors return `Optional.empty()` at [`AttributeResolverDescriptor.java:85-87`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeResolverDescriptor.java`) before calling `context.getClock()` or `AttributeSet.builder(this)...build()`, whereas `resolve` (`:176, 197-198`) always requires a non-null `Clock` (`Objects.requireNonNull` at [`AttributeSet.java:210`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeSet.java`)) and calls `ticker.instant()` only to discard `s` when `s.isEmpty() && s.isComplete()`.
- **Fix**: In [`PreparedContext.getCurrentDateTime()`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/AttributeResolverDescriptor.java`), derive `ZonedDateTime.now(clock)` from the already-captured `clock` (or only build the `AttributeSet` in `resolve` when at least one attribute function returned a non-null bag or failed).
