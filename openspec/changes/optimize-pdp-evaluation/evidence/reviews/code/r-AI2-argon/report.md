### `P2-1` — Data race on the precheck slot in `RootEvaluationContext` under parallel custom combining algorithms

- **Location:** [`RootEvaluationContext.java:94-96`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), [`RootEvaluationContext.takePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), [`RootEvaluationContext.leave`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`)
- **Evidence (`SUPPORTED`):**
  [`RootEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) stores plain `Object prechecked` and `MatchResult precheckedResult` alongside `volatile Thread precheckedThread`.
  1. In [`leave`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), the check-then-act sequence
     ```java
     Thread owner = precheckedThread;
     if(owner != null && owner != Thread.currentThread()){
         return false;
     }
     prechecked = child;
     precheckedResult = result;
     precheckedThread = Thread.currentThread();
     ```
     is not atomic. If a custom combining algorithm evaluates children in parallel across threads `T1` and `T2` sharing one [`RootEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), both threads can read `precheckedThread == null` simultaneously:
     - `T2` calls [`evaluatePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) for matching child `C2` (`leave(C2, MatchResult.MATCH)`), writing `precheckedResult = MATCH`.
     - `T1` interleaves in `leave(C1, MatchResult.NOMATCH)`, overwriting `precheckedResult = NOMATCH`.
     - `T2` finishes writing `prechecked = C2` and `precheckedThread = T2`, then enters `C2.evaluate(C2.createContext(context))` $\to$ [`BaseDecisionRule.isMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`).
     - In [`takePrechecked(C2)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), `T2` observes `owner == T2` and `child == C2`, and consumes `T1`'s `MatchResult.NOMATCH`, turning an applicable `PERMIT`/`DENY` child `C2` into `NOT_APPLICABLE`.
  2. In [`takePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), the volatile release `precheckedThread = null` is executed *before* clearing `prechecked = null; precheckedResult = null;`, allowing another thread that observes `precheckedThread == null` in `leave` to have its new writes overwritten by `takePrechecked`'s trailing `null` assignments.
- **Severity rationale (`P2`):** Built-in combining algorithms are single-threaded per decision, so standard PDP evaluation does not hit this race. However, [`DecisionCombiningAlgorithms.evaluateIfMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/DecisionCombiningAlgorithms.java`) and [`isDefinitelyNoMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/DecisionCombiningAlgorithms.java`) are public SPI helpers whose implementation in [`RootEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) explicitly claims safe fallback when another thread is active.
- **Suggested Fix (zero-allocation, removes volatile traffic on the hot path):**
  Record `private final Thread decidingThread = Thread.currentThread();` on [`RootEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) at construction, expose package-private `boolean isDecidingThread() { return Thread.currentThread() == decidingThread; }`, check `root.isDecidingThread()` in [`TargetBeforeContext.precheck`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/TargetBeforeContext.java`) (returning `UNKNOWN` on any other thread) and at the start of [`RootEvaluationContext.takePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) (returning `Optional.empty()` on any other thread), and drop `volatile Thread precheckedThread`. Then `prechecked` and `precheckedResult` remain plain fields strictly confined to `decidingThread`.

### `P3-1` — Stale `(child, MATCH)` slot state on abnormal exit or unconsumed `isDefinitelyNoMatch`, and skipped `isEvaluationContextValid` on `MATCH`

- **Location:** [`RootEvaluationContext.java:533-553`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`), [`BaseDecisionRule.java:190-199`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`)
- **Evidence (`SUPPORTED`):**
  1. [`RootEvaluationContext.evaluatePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) writes `(child, result)` via `leave(child, result)` and then runs `return result == MatchResult.NOMATCH ? evaluateNoMatch(context, child) : child.evaluate(child.createContext(context));` without a `try / finally` clear. Likewise, when [`DecisionCombiningAlgorithms.isDefinitelyNoMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/DecisionCombiningAlgorithms.java`) is called on a `MATCHED` child, [`RootEvaluationContext.skipPrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) leaves `(child, MatchResult.MATCH)` in the slot and returns `false`.
  2. Another rule cannot consume that slot (`takePrechecked` checks `child != rule && !(child instanceof PinnedReference pin && pin.target() == rule)`), and the same rule's target plan cannot evaluate to a different target match result during the same decision. However, if `child.createContext(context)` throws, or if a custom caller of [`DecisionCombiningAlgorithms.isDefinitelyNoMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/DecisionCombiningAlgorithms.java`) does not immediately follow a `false` return with `child.isMatch(...)`, `(child, MatchResult.MATCH)` stays in the slot.
  3. In [`BaseDecisionRule.isMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`):
     ```java
     Optional<MatchResult> prechecked = RootEvaluationContext.from(context).takePrechecked(this);
     if(prechecked.isPresent()){
         MatchResult r = prechecked.get();
         log.debug("Target evaluation result for id=\"{}\" is \"{}\"", id, r);
         return r;
     }
     if(!isEvaluationContextValid(context)){
         return MatchResult.INDETERMINATE;
     }
     ```
     `isEvaluationContextValid(context)` is skipped for *both* `NOMATCH` and `MATCH`. Skipping it is necessary for `NOMATCH` (where `evaluateNoMatch` passes the parent context), but for `MATCH` the child was given `child.createContext(context)`. If `child.createContext(context)` returned an invalid context (for example, a reference cycle or resolution error where `createContext` returns the enclosing context rather than a context scoped to `this`), returning `MatchResult.MATCH` before checking `isEvaluationContextValid(context)` bypasses the context validity guard.
- **Suggested Fix:**
  1. Wrap the body of [`RootEvaluationContext.evaluatePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) in a `try / finally` that clears `prechecked = null; precheckedResult = null;` if still set (for a `MATCH` composite child, its own `isMatch` at the start of `evaluateRule` already clears the slot before any grandchild runs).
  2. In [`BaseDecisionRule.isMatch`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`), enforce `isEvaluationContextValid(context)` when `r == MatchResult.MATCH`:
     ```java
     if(prechecked.isPresent()){
         MatchResult r = prechecked.get();
         if(r == MatchResult.MATCH && !isEvaluationContextValid(context)){
             return MatchResult.INDETERMINATE;
         }
         log.debug("Target evaluation result for id=\"{}\" is \"{}\"", id, r);
         return r;
     }
     ```
