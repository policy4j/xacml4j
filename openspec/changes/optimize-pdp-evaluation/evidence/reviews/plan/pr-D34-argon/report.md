- **On the observed path, one `DecisionObservation` and one `ArrayDeque` are allocated per decision. Is there a simpler shape that is also clean and allocation-free per callback?**
  - **Yes (`P3-1`).** Instead of maintaining a heap `ArrayDeque<S>` (plus its `Object[16]` backing array) inside `DecisionObservation`, `DecisionObservation` can hold a single field `private S current` (initialized to `decisionToken`) and use the **Java call stack** to save and restore the parent token at the 6 lexical start/finish sites:
    ```java
    Object prev = o.evaluationStarted(context, this);
    Decision d;
    try {
        d = evaluateRule(context);
    } catch (Throwable t) {
        o.evaluationFailed(context, this, prev, t);
        throw t;
    }
    o.evaluationFinished(context, this, prev, d);
    ```
    Inside `DecisionObservation`:
    - `evaluationStarted` reads `S prev = this.current; S next = Objects.requireNonNull(observer.evaluationStarted(prev, context, rule)); this.current = next; return prev;`
    - `evaluationFinished` / `evaluationFailed` reads `S span = this.current; this.current = (S) prev; observer.evaluationFinished(span, context, rule, d);`
    - Point callbacks (`targetMatched`, `attributeResolved`, `functionFailed`, etc.) simply pass `this.current`!
    This removes the `ArrayDeque` and `Object[16]` allocation on every observed decision, eliminates `null`-element vs. empty-stack bookkeeping, guarantees token balance by construction with the Java call stack, and still keeps `<S>` completely erased (`Object prev`) at the 6 call sites.

## 2. Findings (P1 to P3)

### [P2-1] `decisionFinished` in `DefaultPolicyDecisionPoint.requestDecision` must run outside the `try/catch` that invokes `decisionFailed`
- **File:line**: [`REPORT-D34b-opus.md:157, 264-265, 313`](`.ntm/worktrees/xacml4j--batch2/cc_1/REPORT-D34b-opus.md`), [`design.md:1223, 1269`](`openspec/changes/optimize-pdp-evaluation/design.md`), [`DefaultPolicyDecisionPoint.java:141-180`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultPolicyDecisionPoint.java`).
- **Issue**: Line 157 specifies that *"Every start that returns gets **exactly one** finish or failure callback."* In `decide` (`:214-221`) and `evaluate` (`:244-251`), `requestFinished` and `evaluationFinished` are outside the `try/catch` that calls `requestFailed` / `evaluationFailed`. However, the emission table at `:264-265` states: *"`decisionFinished` after the cache put at `:175-179`; `decisionFailed` for anything thrown in `:141-179`"*. If `o.decisionFinished(r)` (on either the cache-hit path at `:156` or the evaluated path at `:180`) is inside the `try` block whose `catch (Throwable t)` calls `o.decisionFailed(t)`, then when `observer.decisionFinished` throws (tested in `36.3` at `:395`), `o.decisionFailed(t)` will also be called for the same decision, violating the single-terminal-callback contract.
- **Fix**: Place `o.decisionFinished(r)` **after** the `try { ... } catch (Throwable t) { o.decisionFailed(t); throw t; }` block of `requestDecision` on both the cache-hit and cache-miss paths:
  ```java
  Result r;
  try {
      ...
  } catch (Throwable t) {
      observation.decisionFailed(t);
      throw t;
  }
  observation.decisionFinished(r);
  return r;
  ```

### [P2-2] Disable further non-terminal emissions in `DecisionObservation` once an observer callback throws (`firstObserverException != null`)
- **File:line**: [`REPORT-D34b-opus.md:288-291`](`.ntm/worktrees/xacml4j--batch2/cc_1/REPORT-D34b-opus.md`), [`design.md:1250-1255`](`openspec/changes/optimize-pdp-evaluation/design.md`), [`DefaultEvaluationContextHandler.java:270-286`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`), [`BaseDecisionRule.java:137-144`](`xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`), [`BaseCompositeDecisionRule.java:132-137, 193-196`](`xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`).
- **Issue**: When an observer callback throws a `RuntimeException` inside an engine `catch (Exception e)` guard:
  1. In [`DefaultEvaluationContextHandler.doPipResolve`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`), `resolve(context, entitySelector)` is inside `try { ... } catch (Exception e) { throw failed(ref, e); }`. An observer `RuntimeException` thrown by `attributeResolved` for `entitySelector` is caught at `:284`, wrapped into `AttributeReferenceEvaluationException`, and immediately reported back to the observer via `o.attributeFailed(context, ref, ...)` as a fake attribute failure.
  2. In [`BaseDecisionRule.isMatch`](`xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`), an observer `RuntimeException` thrown by `attributeResolved` or `functionFailed` inside `target.match(context)` is caught at `:139`, turning the target into `MatchResult.INDETERMINATE`, emitting a fabricated `targetMatched(..., INDETERMINATE)` at `:143`, and causing [`BaseCompositeDecisionRule.evaluate`](`xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`) to run a spurious `getExtendedIndeterminate` pass with `extendedIndeterminateStarted` and child callbacks before `throwObserverFailure()` runs at the root.
- **Fix**: In `DecisionObservation`, make `isEnabled()` return `enabled && firstObserverException == null` so that once any observer callback throws, all subsequent point callbacks (`targetMatched`, `conditionEvaluated`, `attributeResolved`, `attributeFailed`, `functionFailed`, `childrenSelected`, `responsesStaged`) and new child `*Started` callbacks are skipped while the already-started tokens unwind through their `*Finished` / `*Failed` callbacks to `throwObserverFailure()` at the root.

### [P2-3] Emit `functionFailed` for `TypeAssertion` dynamic-type rejections on eager functions and move argument evaluation outside `FunctionSpecBuilder`'s `FunctionInvocationException` wrapper
- **File:line**: [`REPORT-D34b-opus.md:133-137, 276-281`](`.ntm/worktrees/xacml4j--batch2/cc_1/REPORT-D34b-opus.md`), [`TypeAssertion.java:71-79`](`xacml-core/src/main/java/org/xacml4j/v30/policy/TypeAssertion.java`), [`FunctionSpecBuilder.java:442-514`](`xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`).
- **Issue**:
  1. Static type errors in [`Apply.java:258-261`](`xacml-core/src/main/java/org/xacml4j/v30/policy/Apply.java`) emit `functionFailed`, but dynamic-type arguments (`DynamicType`, [`Apply.java:102-124, 197-199`](`xacml-core/src/main/java/org/xacml4j/v30/policy/Apply.java`)) are checked when the argument expression is evaluated in [`TypeAssertion.evaluate`](`xacml-core/src/main/java/org/xacml4j/v30/policy/TypeAssertion.java`), which throws `new FunctionInvocationException(function, Apply.NOT_TYPE_CORRECT, function.getId())`. Once 36.2 separates argument evaluation from the implementation call in `FunctionSpecBuilder`, a `TypeAssertion` failure on an eager function (`!function.isRequiresLazyParamEval()`) will emit **zero** `functionFailed` callbacks.
  2. In [`FunctionSpecBuilder.java:445-514`](`xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`), `doInvoke` (`:486-494`) and `invokeDirect` (`:445-457`, `:464-475`) wrap `Exception e` into `FunctionInvocationException` *outside* `invokeNormalized` (`:502-514`), and also keep `arg0.evaluate`/`arg1.evaluate`/`normalize` inside that `try/catch`. Emitting `functionFailed` inside `invokeNormalized` before `doInvoke` wraps a non-`EvaluationException` `Exception` lacks the `EvaluationException` instance that the call propagates, and keeping `arg0.evaluate` inside `catch (Exception e)` wraps any observer `RuntimeException` thrown during argument evaluation into a `FunctionInvocationException`.
- **Fix**:
  1. In [`TypeAssertion.java:74-77`](`xacml-core/src/main/java/org/xacml4j/v30/policy/TypeAssertion.java`), when `!parameter.isValidParamType(value.getEvaluatesTo())`, create `FunctionInvocationException ex = new FunctionInvocationException(function, Apply.NOT_TYPE_CORRECT, function.getId());`, emit `o.functionFailed(context, function, ex)` if `!function.isRequiresLazyParamEval()` and `o.isEnabled()` (for lazy functions, `TypeAssertion.evaluate` runs inside `invocation.invoke` and is reported at `FunctionSpecBuilder.java:513`), and throw `ex`.
  2. In [`FunctionSpecBuilder.java:442-514`](`xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`), evaluate `normalize` and eager arguments (`arg0.evaluate`, `arg1.evaluate`, `evaluateInPlace`, `evaluate`) *before* the `try/catch` that wraps implementation failures into `FunctionInvocationException`, and emit `o.functionFailed(context, this, ex)` in the `catch` blocks after constructing `FunctionInvocationException`.

### [P3-1] Replace `ArrayDeque<S>` in `DecisionObservation` with a Java-stack-restored `current` field and drop the `<S>` type parameter from `DecisionObservation`
- **File:line**: [`REPORT-D34b-opus.md:92-103, 166-206, 242-251, 440`](`.ntm/worktrees/xacml4j--batch2/cc_1/REPORT-D34b-opus.md`), [`design.md:1192-1215`](`openspec/changes/optimize-pdp-evaluation/design.md`).
- **Issue**:
  1. `DecisionObservation` currently allocates an `ArrayDeque<S>` (plus `Object[16]`) on every observed decision just to save parent tokens across lexical `evaluate` / `getExtendedIndeterminate` calls that are already frames on the Java call stack.
  2. `DecisionObservation<S>` has a type parameter `<S>` that no caller uses (`EvaluationContext`, `RootEvaluationContext`, and `PolicyDecisionPointContext` all use `DecisionObservation<?>`).
  3. Minor doc count: [`REPORT-D34b-opus.md:440`](`.ntm/worktrees/xacml4j--batch2/cc_1/REPORT-D34b-opus.md`) says "19 callbacks", whereas `DecisionObserver<S>` (`:46-77`) defines 20 callbacks.
- **Fix**:
  1. Have `DecisionObservation` hold `private S current` (initialized to `decisionToken`), return `Object prev` from `evaluationStarted` / `extendedIndeterminateStarted` to a local variable at the 6 lexical call sites, and pass `prev` into `evaluationFinished` / `evaluationFailed` / `extendedIndeterminateFinished` / `extendedIndeterminateFailed` to restore `this.current = (S) prev` before invoking the observer callback. This eliminates the `ArrayDeque` allocation per observed decision and makes token balance structural.
  2. Make `DecisionObservation` non-generic publicly (`public final class DecisionObservation`, with `public static <S> DecisionObservation start(DecisionObserver<S> observer, ...)`).
