### Findings

#### `P2-1` — Resolver span placement in `DefaultPolicyInformationPoint` unbalances the token stack on empty candidates, selector path errors, and `Error`s, and places designator `resolverFinished` inside `catch (Exception e)`
- **Locations**:
  - [`design.md:1077-1080`](`openspec/changes/optimize-pdp-evaluation/design.md`), [`design.md:1331`](`openspec/changes/optimize-pdp-evaluation/design.md`)
  - [`DefaultPolicyInformationPoint.java:77-111`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`), [`:128-136`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`), [`:160-200`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`)
- **Evidence**:
  [`design.md:1331`](`openspec/changes/optimize-pdp-evaluation/design.md`) specifies:
  > "`DefaultPolicyInformationPoint.java:77-111` (designators) and `:160-200` (selectors): one span per candidate, starting before the candidate's guard at `:79` and `:164`; `resolverCacheHit` when `cache.getAttributes` (`:83`) or `cache.getContent` (`:168`) returns a value; the finish after the guard, before `return r` (`:100`, `:194`); `resolverFailed` in the `catch` at `:108` and `:180`, with the mapped failure"
  1. **Fallback candidate returning `Optional.empty()`**: When a candidate returns no value (`value` is empty, or `r` is empty at [`:99`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`) / [`:193`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`) and the loop advances to the next candidate), lines `:100` and `:194` (`return r;`) are not reached. If `resolverFinished` only runs before `return r`, a candidate that yields `Optional.empty()` never calls `resolverFinished(..., Optional.empty())`, leaving `this.current` set to the first candidate's resolver token so the next candidate nests inside it instead of the attribute token.
  2. **Designator `return r` at `:100` is inside `try/catch (Exception e)` (`:79-110`)**: In [`DefaultPolicyInformationPoint.java:79-110`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`), `return r;` at `:100` is inside the `try` block caught at `:108`. Calling `o.resolverFinished` inside that `try` means an exception thrown by `observer.resolverFinished` is caught at `:108`, mapped as a resolver failure, and passed to `o.resolverFailed` on the already-finished span while continuing the fallback loop.
  3. **Selector path error at `:190-191` and `Error`s**: In [`DefaultPolicyInformationPoint.java:186-195`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`), `c.getContent().resolve(selectorKey)` runs *outside* `try/catch (Exception e)` (`:164-185`) so a path error aborts the candidate loop immediately and is mapped by [`DefaultEvaluationContextHandler.java:404-411`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`) (`resolveViaPip`). Although [`design.md:1079-1080`](`openspec/changes/optimize-pdp-evaluation/design.md`) states *"A selector path error on the resolver's content counts too"*, placing `resolverFailed` only at `:180` misses exceptions from `:190-191` (and any `Error` in either `resolve` method), leaving the resolver span unclosed and `this.current` unrestored.
  4. **Second failing candidate in `firstFailure` (`:128-136`)**: [`firstFailure`](`xacml-pdp/src/main/java/org/xacml4j/v30/spi/pip/DefaultPolicyInformationPoint.java`) returns `first != null ? first : mapped`. When a second candidate fails after an earlier candidate failed, `resolverFailed` for the second candidate must receive that candidate's `mapped` exception, not `first`.
- **Fix**:
  - In both `resolve` loops of `DefaultPolicyInformationPoint`:
    - Inside the candidate's `try` block, resolve `Optional<BagOfValues> r` (including `value.get().rethrowFailure(designatorKey.getAttributeId())` at `:103` for designators so D26 per-attribute failures are caught as resolver failures).
    - In `catch (Exception e)`, map `AttributeReferenceEvaluationException mapped = AttributeReferenceEvaluationException.forResolverFailure(key, e);`, set `if (failure == null) failure = mapped;`, call `o.resolverFailed(context, d.getId(), key, parent, mapped)`, and `continue`.
    - For selector content evaluation at `:190-191`, catch `Exception e`, map `AttributeReferenceEvaluationException mapped = AttributeReferenceEvaluationException.forResolverFailure(selectorKey, e);`, call `o.resolverFailed(context, d.getId(), selectorKey, parent, mapped)`, and `throw mapped;` immediately (aborting the candidate loop).
    - Catch `Throwable t` (for `Error`s) to call `o.resolverFailed(context, d.getId(), key, parent, t)` and rethrow `t`.
    - After the candidate's `try/catch` (outside the guard), call `o.resolverFinished(context, d.getId(), key, parent, r)` whether `r` is present or `Optional.empty()`, then `if (r.isPresent()) return r;`.

#### `P2-2` — `resolvedFrom(INFORMATION_POINT)` at `DefaultEvaluationContextHandler.java:311-317` overwrites `INFORMATION_POINT_MEMO` from `:332-335`
- **Locations**:
  - [`design.md:1330`](`openspec/changes/optimize-pdp-evaluation/design.md`)
  - [`DefaultEvaluationContextHandler.java:301-337`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`)
- **Evidence**:
  [`design.md:1330`](`openspec/changes/optimize-pdp-evaluation/design.md`) places `INFORMATION_POINT_MEMO` at `:332-335` (inside `resolveWith`) and `INFORMATION_POINT` at `:311-312` and `:314-317` (inside `resolveOnce`). If `resolveOnce` sets `resolvedFrom(INFORMATION_POINT)` after `resolveWith` returns at `:312` or `:315-317`, it overwrites the `INFORMATION_POINT_MEMO` that `resolveWith` set at `:332-335`. - **Fix**:
  - Set `o.resolvedFrom(AttributeSource.INFORMATION_POINT)` in `resolveWith` at [`:336`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`) *after* `ScopedValue.where(ANCESTRY, frame).call(attempt::get)` returns, and in `resolveOnce` at [`:312`](`xacml-pdp/src/main/java/org/xacml4j/v30/pdp/DefaultEvaluationContextHandler.java`) only on the `outcome(running)` branch *after* `outcome(running)` returns (passing `DecisionObservation o` into `resolveOnce`/`resolveWith`).
  - In `DecisionObservation.attributeResolved`, consume and reset `this.resolvedFrom` (`AttributeSource source = Preconditions.checkNotNull(this.resolvedFrom, "resolvedFrom"); this.resolvedFrom = null;`) before invoking `observer.attributeResolved(...)` so a missed return path fails fast instead of reusing a stale source.
