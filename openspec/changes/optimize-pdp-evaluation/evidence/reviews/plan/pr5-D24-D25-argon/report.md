## 2. Findings (Severity-Ordered, P1 to P3)

### [P1-1] Concurrent decision miss + generation pin causes `PinnedReference.evaluate` to run `target.getExtendedIndeterminate` on an invalid context and `TargetIndex` to skip a missed reference
- **Location**: `design.md:604-613, 677, 679-683` (`REPORT-D24e-opus.md:83-92, 156, 158-162`); compare `PolicyIDReference.java:70-98`, `PolicySetIDReference.java:74-102`, `BaseCompositeDecisionRule.java:118, 152, 189-203`, `BaseDecisionRule.java:130`.
- **Failure scenario**: `Generation` is shared across concurrent decisions (`D1`, `D2`), while `misses` is per-decision (`RootEvaluationContext`). Suppose `D1` resolves `ref` in `PolicySet1` and gets a miss (`no policy`) or a non-matching target (`wrongTarget`), recording `ref` in `D1.misses`. In the same generation (without a repository event, e.g., a custom/flaky repository as in test `23.1(c)`), `D2` resolves `ref` in `PolicySet2`, gets a matching `target`, puts `ref -> target` into `Generation.targets`, and publishes `PreparedList` for `PolicySet2` with `PinnedReference(ref, target)` (and if `targetIndex` is on, classifies it under `target.getTarget()`). Now `D1` evaluates `PolicySet2` using that published `PreparedList`:
  1. **When visited**: `PinnedReference.createContext(context)` calls `ref.createContext(context)` (`design.md:680`) -> `context.resolve(ref)`. Because `RootEvaluationContext.resolve(ref)` checks `D1.misses` **before** `Generation.targets` (`design.md:605-610`), `resolve(ref)` replays `D1.misses`: on a recorded miss it throws `PolicyResolutionException`, which `ref.createContext` catches and returns `refContext` (`getCurrentPolicy() == null`, `PolicyIDReference.java:83-85`); on a recorded mismatch it returns `wrongTarget.createContext(refContext)` (`getCurrentPolicy() == wrongTarget`).
  2. Next, the combining algorithm calls `PinnedReference.evaluate(refContext)` (`design.md:682`), which calls **`target.evaluate(refContext)` directly** instead of `ref.evaluate(refContext)`.
  3. Inside `target.evaluate(refContext)` (`BaseCompositeDecisionRule.java:118`), `target.isMatch(refContext)` (`BaseDecisionRule.java:130`) sees `!target.isEvaluationContextValid(refContext)` (`Policy.java:178`) and returns `MatchResult.INDETERMINATE`. Instead of returning `Decision.INDETERMINATE` as `PolicyIDReference.evaluate` does (`PolicyIDReference.java:93`), `BaseCompositeDecisionRule.evaluate` (`line 152`) calls `target.getExtendedIndeterminate(...)` (`lines 189-203`), which evaluates `target.combineDecisions(...)` over `target`'s rules on the wrong context and can return `Decision.NOT_APPLICABLE`, `INDETERMINATE_P`, or `INDETERMINATE_D` instead of `Decision.INDETERMINATE` (or throw `IllegalArgumentException` if a variable of `target` is evaluated against `wrongTarget`'s context at `Policy.java:297`).
  4. **With `targetIndex` on**: `PolicySet2`'s `TargetIndex` indexed `PinnedReference(ref, target)` under `target.getTarget()` (`design.md:677`) instead of `Any`. If `D1`'s request does not match `target.getTarget()`, `TargetIndex` skips the position as `NotApplicable` instead of visiting `ref` and replaying `D1.misses`.
- **Smallest fix**:
  1. Add a package-private `EvaluationContext createContext(EvaluationContext context, CompositeDecisionRule target)` on `PolicyIDReference` and `PolicySetIDReference` that runs today's guard, constructs `new Policy(Set)IDReferenceEvaluationContext(context)` (preserving the parent and cycle checks), and returns `target.createContext(refContext)` directly.
  2. In `PinnedReference`: if `!RootEvaluationContext.isMissed(context, ref)` (`root.misses == null || !root.misses.containsKey(ref)`), `createContext` calls `ref.createContext(context, target)` and `evaluate`/`isMatch` call `target` directly; if `RootEvaluationContext.isMissed(context, ref)` is `true`, `createContext`, `evaluate`, and `isMatch` delegate to `ref`.
  3. In `Prepared.children(context, set)`: apply `TargetIndex` candidate filtering only when `root.misses == null` (when a decision has recorded a miss/failure/mismatch in `misses`, return the unfiltered `PreparedList`).
- **Test that catches it**: In one generation (no repository event), a custom repository returns `null` on lookup 1 of `ref` and a matching `Policy` (with `Target` `x` and a single `Rule` whose target does not match) on lookup 2. Decision 1 resolves `ref` in `PolicySet1` (recording `no policy` in `D1.misses`), then a condition hook triggers Decision 2 to prepare `PolicySet2` (which references `ref` under `deny-overrides`), and Decision 1 then evaluates `PolicySet2` for request `y`. Assert Decision 1's result for `PolicySet2` is `Indeterminate` (matching `PolicySet1`), not `NotApplicable`.

### [P2-1] `PinnedReference.createContext(context)` calling `ref.createContext(context)` (`design.md:680`) retains a `ConcurrentHashMap.get(ref)` probe per visited child, and `design.md:577-578` misstates context removal for pinned children
- **Location**: `design.md:577-578, 680, 787-788` (`REPORT-D24e-opus.md:56-57, 159-160, 266-267`); compare `PolicyIDReference.java:78`, `PolicySetIDReference.java:82`.
- **Failure scenario**:
  1. `design.md:787-788` states that D24/D25 removes *"the resolver probes, and the `isReferenceTo` matches"*. However, if `PinnedReference.createContext(context)` delegates to `ref.createContext(context)` (`design.md:680`), it still calls `context.resolve(ref)` -> `RootEvaluationContext.resolve(ref)` -> `Generation.targets.get(ref)` (`ConcurrentHashMap.get(ref)`) on **every visited `PinnedReference`**. When `targetIndex` is off (the default) or for `Any` children, moving `ConcurrentHashMap.get(ref)` from `DefaultPolicyReferenceResolver` to `Generation.targets` does not eliminate the per-reference hash-map probe.
  2. `design.md:577-578` states: *"the policy and reference contexts of the children are 95% of synthetic:1000 bytes. This design removes them for skipped and pinned children."* A visited pinned child still builds both `Policy(Set)IDReferenceEvaluationContext` and `Policy(Set)DescendantEvaluationContext`; contexts are removed only for *skipped* children, while resolver probes and `isReferenceTo` checks are removed for *pinned* children.
- **Smallest fix**: Use `ref.createContext(context, target)` from **P1-1** in `PinnedReference.createContext(context)` when `!RootEvaluationContext.isMissed(context, ref)` (zero map lookup per visited pinned child), and amend `design.md:577-578` to match `design.md:787-788`.
- **Test that catches it**: Verified by the JMH batch pair (`tasks.md:191, 249`) with `targetIndex=false` and `targetIndex=true`.

### [P2-2] `Policy.combineDecisions` (`design.md:691`) does unnecessary `Generation` map lookups and list preparation when `targetIndex` is off
- **Location**: `design.md:691` (`REPORT-D24e-opus.md:170`); compare `Policy.java:56, 72, 172-174`.
- **Failure scenario**: Unlike `PolicySet.decisionRules`, `Policy.rules` (`Policy.java:56, 72`) is an `ImmutableList<Rule>` of inline rules only (XACML 3.0 has no rule references to pin). When `targetIndex` is `false` (the default configuration), preparing a `Policy` in `Generation` produces an unchanged `rules` list with a `null` `TargetIndex`, adding a context-root check and `Generation` identity-map lookup (`ConcurrentMap.get(policy)`) to every `Policy.combineDecisions` invocation for zero gain.
- **Smallest fix**: In `Prepared.rules(context, policy)` (or `Policy.combineDecisions`), check whether `targetIndex` is enabled on the generation first; when `targetIndex` is `false`, return `policy.getRules()` directly without consulting or populating the generation's map.
- **Test that catches it**: Differential baseline comparison (`tasks.md:149-150`) and JMH on `rsa2008` with `targetIndex=false`.

### [P3-1] Pass the live `EvaluationContext` (never `null`) to `FunctionSpec.scan` probes, and keep `enableRefCache = true` in the 7-argument baseline factory constructor
- **Location**: `design.md:708, 722-723` (`REPORT-D24e-opus.md:187, 201-202`); compare `FunctionSpecBuilder.java:325-328` and `PolicyDecisionPointContextFactory.java:81-96`.
- **Failure scenario**:
  1. `FunctionSpecImpl.scan(EvaluationContext context, Value<?> literal, BagOfValues bag)` (`FunctionSpecBuilder.java:326`) evaluates `context.isValidateFuncParamsAtRuntime()` without a null check; passing `null` for `context` in the two `TargetIndex` `scan` probes throws `NullPointerException`. Passing the live `EvaluationContext` avoids `NullPointerException` and automatically returns `BagStorage.Scan.NONE` when runtime parameter validation is enabled (`23.1(g)`).
  2. In `DefaultPolicyDecisionPointContextFactory` (`PolicyDecisionPointContextFactory.java:81-96`), the existing 7-argument package-private constructor is used as the unprepared baseline in tests (`design.md:722-723`, `tasks.md:149-150`). Ensure the 7-argument constructor retains `new DefaultPolicyReferenceResolver(repository)` (cache enabled, no registry listener), while the new overload taking `PreparedPolicySets` constructs `new DefaultPolicyReferenceResolver(repository, false, 1024)`.
- **Smallest fix**: Pass `context` to `predicate.scan(context, ...)` during `TargetIndex` construction, and keep `new DefaultPolicyReferenceResolver(repository)` in the 7-argument baseline constructor.
- **Test that catches it**: Task `23.1(g)` ("runtime validation on") with `targetIndex()` enabled, and Task `23.1` baseline comparisons.
