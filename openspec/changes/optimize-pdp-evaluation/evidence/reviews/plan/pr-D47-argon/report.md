## Executive Summary

Design decision **D47** is sound in principle and well-scoped. Borrowing the enclosing policy's evaluation context via two private fields (`activeRule` and `activeRuleStatus`) on [`Policy.PolicyDescendantEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`) eliminates the `32 B` [`Rule.RuleEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`) wrapper per evaluated rule at a cost of `+8 B` per policy context (`32 -> 40 B` for `PolicyDescendantEvaluationContext`; `40 -> 48 B` for `PolicyIDReference.ReferencedPolicyContext`), while leaving [`RootEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) at `80 B`.

Two **P2** boundary conditions and two **P3** implementation/accounting details should be tightened before or during the build so that implementation matches the design's soundness and allocation guarantees:

1. **[P2-1] Construction-time expression eligibility must check `FunctionReference` targets, handle `TypeAssertion` wrappers, and guard `VariableDefinition` DAGs (`design.md:1779-1785`)**:
   - In higher-order calls (`any-of`, `all-of`, `any-of-any`, `all-of-any`, `all-of-all` in [`HigherOrderFunctions.java`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/HigherOrderFunctions.java`)), the outer [`Apply`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Apply.java`) uses a built-in `FunctionSpec` (`FunctionSpecBuilder.usesBuiltInInvocation(apply.function()) == true`), while its first argument in `apply.getArguments()` is a [`FunctionReference`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/FunctionReference.java`) that invokes `ref.function().invoke(context, ...)` with the rule's `EvaluationContext`. The scanner must require `ref.getClass() == FunctionReference.class && FunctionSpecBuilder.usesBuiltInInvocation(ref.function())`.
   - `Apply.Builder` wraps `DynamicType` arguments in package-private [`TypeAssertion`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/TypeAssertion.java`) ([`Apply.java:138, 307`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Apply.java`)); the scanner must either reject `TypeAssertion` or unwrap its inner `argument`.
   - Response expressions must require exact classes [`ObligationExpression.class`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/ObligationExpression.java`), [`AdviceExpression.class`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AdviceExpression.java`), and [`AttributeAssignmentExpression.class`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeAssignmentExpression.java`) (all three are non-final and receive `EvaluationContext` in `evaluate`), and `VariableReference -> VariableDefinition` traversal must track visited `VariableDefinition` instances in a lazily allocated identity set so diamond variable DAGs ([`ApplyArgumentValidationTest.java:231-244`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/ApplyArgumentValidationTest.java`)) or programmatic cycles remain $O(N)$ and terminate.
2. **[P2-2] Parent policy-context recognition and `Policy.BUILT_IN_ALGORITHMS` separation (`design.md:1770-1775, 1833-1836, 1860`)**:
   - At runtime, engine policy contexts are instances of three package-private classes in `org.xacml4j.v30.policy`: [`Policy.PolicyDescendantEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`), [`PolicyIDReference.ReferencedPolicyContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PolicyIDReference.java`) (which subclasses `PolicyDescendantEvaluationContext` for referenced policies in unobserved decisions), and the anonymous subclass in [`Policy.createExtIndeterminateEvalContext()`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`). Because `PolicyDescendantEvaluationContext` is package-private, `context instanceof Policy.PolicyDescendantEvaluationContext` safely covers all three; an exact `getClass() == PolicyDescendantEvaluationContext.class` check would exclude both `ReferencedPolicyContext` (turning `synthetic:100` from `-20.57 B/op` into a `+6.86 B/op` regression) and the policy-pass context.
   - In [`Policy.java:69-81`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`), `BUILT_IN_ALGORITHMS` currently gates [`Policy.canIndexRules()`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`) (D19 rule target indexing) and contains only the 7 XACML 3.0 algorithms. Adding the 4 legacy overrides classes directly to `BUILT_IN_ALGORITHMS` without keeping `canIndexRules()` on its existing 7-class set would silently alter D19 indexing on legacy policies, contradicting [`design.md:1860`](`.ntm/worktrees/xacml4j--batch2/agyx_1/openspec/changes/optimize-pdp-evaluation/design.md`) ("No ... index edit").
3. **[P3-1] Keyed per-rule status recording when borrowing a policy-pass context (`design.md:1818-1823, 1833-1836`)**:
   - On a policy-pass context ([`Policy.java:342-354`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`)), `startsPass() && parent.getEvaluationStatus().isPresent()` is `true` on the borrowed context itself ([`DescendantEvaluationContext.java:107-111`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`)). When a rule is active in the pass context's slot, `setEvaluationStatus(Status)` must record `activeRuleStatus = status`, `top.setEvaluationStatus(activeRule, status)`, and `this.evaluationStatus = status` **before** the `if (startsPass() && parent.getEvaluationStatus().isPresent()) return;` guard, and only after that guard record `(policy, status)` and `parent.setEvaluationStatus(status)`, matching the two-hop `RuleEvaluationContext -> passCtx` chain.
4. **[P3-2] Post-D46 histogram numbers in `design.md:1850-1852`**:
   - On the current post-D46 tree ([`pr23-astra-fixed3-profile.md:153-154`](`.ntm/worktrees/xacml4j--batch2/agyx_1/openspec/changes/optimize-pdp-evaluation/research/pr23-astra-fixed3-profile.md`)), `rules:100 multi-valued` allocates exactly `R = 8` rule contexts (`256 B`) and `P = 8` policy contexts (`256 B`), so the exact saving is `-32(8) + 8(8) = -192 B/op` (rather than `-186.4 B/op` from pre-D46 JFR sampling in `pr22`), and `synthetic:100` saves `-20.57 B/op` (`-27.43 + 6.86 B/op`).

## Point-by-Point Verification

### 1. Soundness (`SUPPORTED`)

- **OASIS XACML 3.0 Plus Errata 01 ([fetched 2026-10-28](https://docs.oasis-open.org/xacml/3.0/errata01/os/xacml-3.0-core-spec-errata01-os-complete.html))**:
  - **§7.11 (`Rule evaluation`)**:
    > *"A rule has a value that can be calculated by evaluating its contents. Rule evaluation involves separate evaluation of the rule's target and condition. The rule truth table is shown in Table 4."*
    Table 4 maps `(Target=Match, Condition=True) -> Effect`, `(Target=Match, Condition=False) -> NotApplicable`, `(Target=Match, Condition=Indeterminate) -> Indeterminate{P|D}`, `(Target=No-match, Condition=Don't care) -> NotApplicable`, and `(Target=Indeterminate, Condition=Don't care) -> Indeterminate{P|D}`.
  - **§7.19 (`Exception handling`)**:
    - **§7.19.1 (`Syntax errors`)**: *"If a syntax error is encountered, then the rule, policy or policy set SHALL evaluate to 'Indeterminate' with a status code value of 'urn:oasis:names:tc:xacml:1.0:status:syntax-error'."*
    - **§7.19.2 (`Processing errors`)**: *"If an operational error occurs during evaluation of a policy, then the rule, policy or policy set SHALL evaluate to 'Indeterminate' with a status code value of 'urn:oasis:names:tc:xacml:1.0:status:processing-error'."*
    - **§7.19.3 (`Missing attributes`)**: *"If the value of the MustBePresent attribute in an `<AttributeDesignator>` or `<AttributeSelector>` element is 'true', and the attribute is absent from the request context, then the rule, policy or policy set SHALL evaluate to 'Indeterminate' with a status code value of 'urn:oasis:names:tc:xacml:1.0:status:missing-attribute'."*
  - **Annex C (`Combining algorithms (normative)`)**:
    - Verified **C.1** (`Extended Indeterminate values`), **C.2** (`Deny-overrides`), **C.3** (`Ordered-deny-overrides`), **C.4** (`Permit-overrides`), **C.5** (`Ordered-permit-overrides`), **C.6** (`Deny-unless-permit`), **C.7** (`Permit-unless-deny`), **C.8** (`First-applicable`), and **C.10–C.13** (`Legacy Deny-overrides`, `Legacy Ordered-deny-overrides`, `Legacy Permit-overrides`, `Legacy Ordered-permit-overrides`).
    - All 11 built-in rule combining algorithms evaluate one rule at a time sequentially via [`DecisionCombiningAlgorithms.evaluateIfMatch(context, rule)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/combine/DecisionCombiningAlgorithms.java`). None of them retains a rule's `EvaluationContext` after `evaluateIfMatch` returns or overlaps two rule evaluations in the same policy context.
- **Status isolation between rules (with `FIX-TSTATUS` merged)**:
  - In [`Rule.evaluateRule`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`), [`AttributeDesignator.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeDesignator.java`), and [`AttributeSelector.doContextResolve`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeSelector.java`), `context.setEvaluationStatusIfAbsent(...)` checks `getEvaluationStatus().isEmpty()`.
  - Under `FIX-TSTATUS`, [`Match.match`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Match.java`) records `context.setEvaluationStatus(rule, e.getStatus())` and, when `rule != null`, `context.setEvaluationStatus(e.getStatus())`.
  - Without a separate `activeRuleStatus` field on `PolicyDescendantEvaluationContext`, Rule 1 failing with `missing-attribute` would set `policyCtx.evaluationStatus = missing-attribute`; if Rule 2 then failed in a way that relies on `setEvaluationStatusIfAbsent(() -> Status.processingError().build())` (e.g., [`Condition.java:102-105`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Condition.java`) catching a non-`EvaluationException` and calling `context.setEvaluationStatus(rule, processingError)` followed by [`Rule.java:147`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`)), `setEvaluationStatusIfAbsent` would see Rule 1's status on `policyCtx` and fail to overwrite `policyCtx` and `root` with Rule 2's `processing-error`.
  - D47's design ([`design.md:1812-1826`](`.ntm/worktrees/xacml4j--batch2/agyx_1/openspec/changes/optimize-pdp-evaluation/design.md`)) cleanly solves this: `activeRuleStatus` starts `null` on each borrowed rule entry, `getEvaluationStatus()` and `setEvaluationStatusIfAbsent` read/write `activeRuleStatus` while `activeRule != null`, and `setEvaluationStatus(Status)` writes `activeRuleStatus`, records `(activeRule, status)` in `top`, sets the policy's `evaluationStatus`, records `(policy, status)` in `top`, and propagates to `parent.setEvaluationStatus(status)`. (See **P3-1** for the exact ordering around `startsPass()`.)
- **Extended-Indeterminate pass**:
  - [`Policy.createExtIndeterminateEvalContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`) still allocates a separate `PolicyDescendantEvaluationContext` pass instance. Eligible rules inside that pass borrow the pass context's slot, never the outer policy context's slot, and [`BaseCompositeDecisionRule.extendedIndeterminatePass`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseCompositeDecisionRule.java`) still clears responses staged during the pass via `clearExtendedIndeterminateResponses(pass)`.
  - Calling `Rule.createExtIndeterminateEvalContext` ([`Rule.java:186-192`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`)) directly still returns a distinct `ExtendedIndeterminateRuleContext`.
- **Response staging**:
  - [`BaseDecisionRule.evaluateObligations`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`) and [`evaluateAdvice`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`) stage responses via `context.addObligations(...)` / `context.addDecisionAdvice(...)`, which delegate through [`DescendantEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`) to `top` (`RootEvaluationContext`). On failure inside an obligation or advice expression when a rule has both obligations and advice, [`BaseDecisionRule.clearStagedResponses(context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`) uses `ResponseStaging` in `RootEvaluationContext`, which is keyed by the rule's own enter/exit in `BaseDecisionRule.evaluate`, not by the `RuleEvaluationContext` instance.
- **Variables**:
  - Variable definitions are policy-scoped (§7.8). In [`RuleEvaluationContext`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`), `getVariableEvaluationResult` and `setVariableEvaluationResult` simply delegated via `DescendantEvaluationContext` to `parent` (`PolicyDescendantEvaluationContext.varDefEvalResults`, [`Policy.java:357-376`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Policy.java`)). Evaluating an eligible rule directly in `PolicyDescendantEvaluationContext` hits the same `varDefEvalResults` map directly (eliminating one delegation hop) and preserves lazy evaluation, cross-rule memoization within the policy evaluation, and undefined-variable errors.

### 2. The Eligibility Proof (`SUPPORTED`)

- **Can a custom expression, function, or callback still receive the borrowed context?**
  - **No**, provided **P2-1** is enforced:
    1. **Decision observation callbacks (`DecisionObservation` / `EvaluationContextHandler`)**: Excluded by the runtime check `!root.getDecisionObservation().isEnabled()` ([`design.md:1772`](`.ntm/worktrees/xacml4j--batch2/agyx_1/openspec/changes/optimize-pdp-evaluation/design.md`)).
    2. **Runtime parameter validators (`FunctionParametersValidator`)**: Excluded both by `!context.isValidateFuncParamsAtRuntime()` ([`design.md:1772`](`.ntm/worktrees/xacml4j--batch2/agyx_1/openspec/changes/optimize-pdp-evaluation/design.md`)) and by `FunctionSpecBuilder.usesBuiltInInvocation` ([`FunctionSpecBuilder.java:301-311`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/FunctionSpecBuilder.java`)).
    3. **Custom `AttributeReferenceResolver` (PIP / designator / selector resolvers)**: [`DescendantEvaluationContext.resolve(AttributeDesignator)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`), `resolve(AttributeSelector)`, and `resolveEntity(CategoryId)` forward directly to `top` (`RootEvaluationContext`), so `AttributeReferenceResolver` implementations always receive `RootEvaluationContext`, never the descendant policy or rule context.
    4. **Custom `FunctionSpec` / `FunctionInvocation` / `@XacmlEvaluationContextParam`**: Excluded when `FunctionSpecBuilder.usesBuiltInInvocation` is checked on every `Match.getPredicate()`, every `Apply.function()`, and every `FunctionReference.function()` (**P2-1**). All built-in functions in `XacmlDefaultFunctions` and `RegExpFunctions.Matching` that accept `@XacmlEvaluationContextParam` (`LogicalFunctions`, `HigherOrderFunctions`, `StringFunctions`, `RegExpFunctions`, `NonNumericComparisonFunctions.timeInRange`, `XPathFunctions`, `AttributeDesignatorFunctions`) were inspected; none retains `context`, tests `instanceof RuleEvaluationContext`, or inspects `getParent()`.
    5. **Custom `Expression` / `PolicyElement` subclasses**: Excluded by requiring exact engine classes (`Rule.class`, `Target.class`, `MatchAnyOf.class`, `MatchAllOf.class`, `Match.class`, `Condition.class`, `ObligationExpression.class`, `AdviceExpression.class`, `AttributeAssignmentExpression.class`, `Apply.class`, `AttributeDesignator.class`, `AttributeSelector.class`, `BagOfValues.class`, `FunctionReference.class`, `VariableReference.class`, `VariableDefinition.class`, and `Value` classes in `org.xacml4j.v30.types` where no class overrides `ValueExp.evaluate`). Note that `QuantifiedExpression` (`QuantifiedForAll`, `QuantifiedForAny`, `QuantifiedMap`, `QuantifiedSelect`) mutates variable bindings via `setVariableEvaluationResult` ([`QuantifiedExpression.java:63`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/QuantifiedExpression.java`)) and is naturally excluded by this allowlist.
- **Is the construction-time flag sound when a rule references variable definitions?**
  - **Yes**: [`VariableReference`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/VariableReference.java`) holds an immutable direct reference to its [`VariableDefinition`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/VariableDefinition.java`) (`ref.getDefinition().getExpression()`) at `Rule` construction time, and `VariableReference.evaluate(context)` ([`VariableReference.java:86`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/VariableReference.java`)) evaluates `this.varDef.evaluate(context)` directly rather than looking up the definition by string ID in `Policy`. Therefore, scanning `ref.getDefinition().getExpression()` (with a visited set per **P2-1**) at `Rule` construction time sees the exact expression tree that `VariableReference.evaluate` can execute at evaluation time.

### 3. The Mechanism (`SUPPORTED`)

- **Entry after `TargetBeforeContext.precheck` and cleanup in `finally`**:
  - In [`TargetBeforeContext.evaluateIfMatch(EvaluationContext context, DecisionRule child)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/TargetBeforeContext.java`):
    1. `precheck(context, child)` runs **before** entering the slot, while `context.getCurrentRule()` is still `null`. Thus the guard `context.getCurrentRule() != null` at [`TargetBeforeContext.java:191`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/TargetBeforeContext.java`) works unchanged.
    2. When `precheck` returns `Optional.of(MatchResult.NOMATCH)`, [`RootEvaluationContext.evaluatePrechecked`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/RootEvaluationContext.java`) calls `child.isMatch(context)` (which consumes the prechecked `NOMATCH` at [`BaseDecisionRule.java:212-214`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`) before calling `isEvaluationContextValid`) and returns `Decision.NOT_APPLICABLE` without setting the slot or creating a rule context.
    3. When `precheck` returns `Optional.of(MatchResult.MATCH)` or `Optional.empty()`, entering the slot around `child.evaluate(child.createContext(context))` sets `activeRule = rule` and `activeRuleStatus = null` on `PolicyDescendantEvaluationContext` before `child.createContext(context)` runs.
    4. Inside [`Rule.createContext(context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`), `isEvaluationContextValid(context)` (`this == context.getCurrentRule() && context.getCurrentPolicy() != null`) returns `true`, so `Rule.createContext(context)` returns `context` directly without allocating `RuleEvaluationContext`.
    5. Inside [`Rule.evaluateRule(context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java`) and [`BaseDecisionRule.isMatch(context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/BaseDecisionRule.java`), `isEvaluationContextValid(context)` also returns `true`.
    6. A `try / finally` block clears `activeRule = null` and `activeRuleStatus = null` on every exit path, including `RuntimeException` and `Error`.
- **Reentrancy and an occupied slot**:
  - If `activeRule != null` when another rule evaluation is attempted on the same policy context, the eligibility check declines borrowing and `Rule.createContext(context)` sees `this != context.getCurrentRule()` and allocates a fresh `RuleEvaluationContext(context)` as today. No stack is needed.
- **`getCurrentRule()` from descendant contexts**:
  - In [`DescendantEvaluationContext.getCurrentRule()`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/DescendantEvaluationContext.java`), walking `for (EvaluationContext c = this; c != top; c = ((DescendantEvaluationContext) c).parent)` and checking `if (c instanceof Rule.RuleEvaluationContext r) return r.rule(); if (c instanceof Policy.PolicyDescendantEvaluationContext p && p.rule() != null) return p.rule();` returns the nearest active rule whether it is held by a `RuleEvaluationContext` or a borrowed `PolicyDescendantEvaluationContext`.
- **D26 workers never see the slot**:
  - D26 parallel attribute pre-resolution runs through `RootEvaluationContext` (`top.resolve`), where worker threads execute with `root.isDecidingThread() == false` and receive `RootEvaluationContext`, never a `PolicyDescendantEvaluationContext`.

### 4. Interaction with D45 (`SUPPORTED`)

- In [`Condition.evaluate(EvaluationContext context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/Condition.java`):
  ```java
  Expression predicate = context.getCurrentPolicy() instanceof Policy policy && policy.mayShareConditions()
          ? PreparedConditions.predicate(context, policy, this)
          : expression;
  ```
- On a borrowed `PolicyDescendantEvaluationContext` (or `ReferencedPolicyContext`), `context.getCurrentPolicy()` still returns `Policy.this` (`DescendantEvaluationContext.getCurrentPolicy()` walks up to `PolicyDescendantEvaluationContext.policy()`, which is unchanged by `activeRule`).
- Inside [`PreparedConditions.predicate(context, policy, this)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PreparedConditions.java`):
  - `DescendantEvaluationContext.topOf(context)` returns the same `RootEvaluationContext` (`top`).
  - `shares(root, context)` checks `root.isDecidingThread()`, `!root.getDecisionObservation().isEnabled()`, `!context.isValidateFuncParamsAtRuntime()`, and `root.hasRequestAttributeResolution()`, all of which return the exact same booleans on the borrowed policy context as on `RuleEvaluationContext`.
  - [`PreparedConditions.Shared.evaluate(context)`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/PreparedConditions.java`) reads and populates `root.valueSnapshots()` keyed by `Canonical` and calls `canonical.readsOneRequestString(context)` (`context.resolveEntity(...)` -> `top.resolveEntity(...)`).
- Because D45's `PreparedConditions.prepare(policy)` stores rebuilt predicates containing `PreparedConditions.Shared` in `root.generation().orElseThrow().conditions` without mutating `Condition.getExpression()`, `Rule`'s construction-time eligibility scan inspects the original `Condition.getExpression()` tree and is unaffected by `Shared`.
