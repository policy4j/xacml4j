## Finding

**P2 — No behavioral test exercises a higher-order function over a request- or PIP-supplied custom `Value` while a rule is eligible for D47 borrowing.** `Rule.Eligibility.expression` accepts every exact `AttributeDesignator` and `AttributeSelector` at `xacml-core/src/main/java/org/xacml4j/v30/policy/Rule.java:302-305`, without knowing the runtime values their resolution returns. `any-of` invokes its `FunctionReference` on values from the evaluated bag with the same context at `xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/HigherOrderFunctions.java:62-74,104-115`; designators resolve at evaluation time (`xacml-core/src/main/java/org/xacml4j/v30/policy/AttributeReference.java:100-117`). A custom returned `Value.evaluate(context)` can therefore distinguish the rule context from the borrowed policy context.

Add a `ParentPolicyValue` (or equivalent context-sensitive `Value.OtherValue`) from **both** the request and a PIP resolver, inside a built-in higher-order invocation in a Rule condition. Compare observed and unobserved results for target index off/on. The existing Sol report gives the concrete oracle: observed evaluation permits, while the faulty borrowed evaluation is NotApplicable. Assert the full `Result` equality and explicit decision/status; include an obligation/advice in a successful branch so a response-content regression is visible. Keep a standard engine `StringVal` case as a control, but it cannot replace either custom-value case.

## Named regression tests

1. `requestSuppliedCustomValueInHigherOrderConditionMatchesObservedResult` — built-in `any-of` and built-in `string-equal` FunctionReference; request designator resolves to a bag containing `ParentPolicyValue`; parameterize indexed false/true and compare observed/unobserved. Require Permit, expected status, and complete result equality.
2. `pipSuppliedCustomValueInHigherOrderConditionMatchesObservedResult` — same expression, request lacks the attribute, PIP returns the custom-valued bag; parameterize index and observation; require Permit and complete result equality.
3. `pipHigherOrderMissingValuePreservesIndeterminateStatusAndResponse` — PIP does not resolve a required attribute; require the observed result's exact Indeterminate decision, status code, and full response equality with both index settings.
4. `firstApplicableDoesNotResolveLaterPipHigherOrderOperand` — an earlier Rule decides before a later PIP-backed higher-order condition; require the earlier decision/result and no resolver call. Then arrange for the later Rule to be reached and assert its expected result.
5. `engineLiteralHigherOrderConditionRetainsOutcomeWithD45Preparation` — repeated shareable built-in predicates and engine literal bags; assert observed/unobserved decision, status, and response equality, with target index off/on.
6. Retain the existing `codeOfAnotherImplementationSeesTheContextOfItsRule` cases as fallback controls. Its target case remains the target-context test; the custom function-reference and custom literal cases must not be counted as evidence for the faulty eligible path.
