## Target precheck proof and change

`TargetBeforeContext.prepare` accepts a plan only for exact engine target and Match classes, request designators, compatible built-in literal values and predicates with a direct scan; `safeValues` checks the literal's class and built-in type. `precheck` requires an eligible unobserved root and reads the request entity and bag directly, without resolving a missing bag through a PIP. Its bag scan does not evaluate each bag value as an expression: unsupported values return `NONE`, which becomes `UNKNOWN`. For the string case the scan checks each value's class before comparing. Missing request bags, custom bag values and other uncertain cases therefore fall back to normal target evaluation.

`evaluateIfMatch` returns immediately for a proven `NOMATCH`. For a proven `MATCH`, `RootEvaluationContext.evaluatePrechecked` leaves an answer for that exact child and calls it; `BaseDecisionRule.isMatch` takes the answer before it could match the target. `takePrechecked` returns empty without clearing the slot if called for a different rule; it clears the slot only for the recorded child or its pin. For the borrowed path the child is an exact `Rule`, observation is disabled, and its context validity check and `isMatch` precede condition or response execution. The answer is therefore consumed before the body, consistent with the lifecycle expected by design D53. `evaluatePrechecked` also clears the slot in `finally`.

`Rule.java:54-102,272-295` now records both the prior structural/body eligibility proof and whether the target has a Match. `TargetBeforeContext.java:80-99` permits `enterRule` for a rule with a Match only after the precheck answered `MATCH`; an undecided target uses a real rule context. `Policy.enterRule` continues to enforce the exact-rule, built-in-algorithm, observation, thread, runtime-validation and body-eligibility gates. No public API or PIP-resolution behavior changed. This restores a borrowing path for prechecked matching targets; its allocation benefit is not measured here.
