76:   - If `start` is killed after the send but before the caller has the id, the natural retry is another `start`, which is a second submission. An agent tool timeout is enough to cause this.
77:   - Rerunning `batch` after a crash resubmits earlier entries.
78:   - `openspec/changes/add-desktop-deep-research/specs/desktop-research-execution/spec.md:75` can be read globally, but nothing enforces it for a new `start`.

80:   - There is no per-job lock, so concurrent `wait` and `collect` can lose updates to `job.json`.

82:   - Keep a user-scoped submission ledger beside the lock, consulted under the lock by `start` and `batch`.

85:   - Write a batch manifest mapping entries to job ids before first input, and make a rerun resume it.
86:   - Add a per-job lock with a revision check, and sync the write-ahead record to disk.
