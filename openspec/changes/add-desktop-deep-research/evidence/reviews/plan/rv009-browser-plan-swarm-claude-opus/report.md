1. HIGH - design.md:570-613 (D13); spec.md:209-229; execution spec:159-165. Account memory and past-chat search are not a "source" in the plan (help pages below). The profile is the operator's real account (design.md:362-364) and temporary chats are excluded (design.md:568). Attack with sanctioned commands: the calling agent, or an instruction in a report it read, writes the prompt "summarize my other conversations"; `follow-up` (chat is the default) passes every precondition; `collect`; the agent reads the printed answer file; `--context-job` then gives it to another provider. A personalized answer does the same with no attacker. Change: name memory, chat-history reference and past-chat search as private sources; verify a characterized off state before entry, else block; refuse a chat child as context job.

2. HIGH - design.md:384-435 (D10). D10 limits tool calls and flags, not the driver's environment, working directory or stderr; the existing helper launch passes no `env=` (native_bridge.py:28). The README revision that the research cites documents environment forms of options (`PLAYWRIGHT_MCP_INIT_SCRIPT`, `PLAYWRIGHT_MCP_IGNORE_HTTPS_ERRORS`). Attack, in the class of the pseudo-terminal case: the agent runs a sanctioned command with `PLAYWRIGHT_MCP_INIT_SCRIPT=<file>`; the script runs in every provider page before the page's scripts. `DEBUG` and proxy variables are further paths (inferred). The output directory (design.md:428-430) is undefined for `doctor`, `inspect`, `status`, `wait` and the harness. Change: a launch contract: fixed allow-listed environment, absolute node path, private working and output directory, stderr dropped, every security option passed explicitly; a fixture test with hostile variables.

3. HIGH - design.md:740-747 (D15); spec.md:325-328. The redaction is circular: names are shown "inside the application regions", but regions come from the provider profile (design.md:536-539), which characterization produces (design.md:436-438). Without a profile the harness cannot tell regions apart, and each conversation-list entry, project and account button is a control whose name is the title or account label (inferred). The fixture pages of gate 5.7 carry "the roles and names of the provider profiles" (design.md:791-793), which exist only after 5.8: the gate tests invented pages. Length plus an unkeyed hash confirms a guessed title. Change: no outline. The agent proposes role and name pairs from a reviewed vocabulary; the harness returns match counts and ancestor roles; the operator reads the first output before any agent.

4. MEDIUM - design.md:465-480 (D11), 873-875. Playwright starts Chromium with `--use-mock-keychain` and `--password-store=basic` (chromiumSwitches.ts on main). `login` without the driver uses the real key, so the driven run likely sees `AUTH_REQUIRED`; "same channel" does not settle it. Signing in under the mock key leaves cookies under a public constant; removing the flags needs a config file (inferred) that the lock must cover. `login` is ordinary Chrome and offers password saving and sync (not fetched). The store is under Application Support (desktop_research.py:871), so backups copy the session. Change: decide key handling before approval; disable password saving and sync for `login`; exclude the profile from backup.

5. MEDIUM - design.md:623-631, 195-199. "Controls ... outside the model" is wrong for plan approval: the scope check is the calling agent reading provider-written plan text. A hostile context report makes the next provider's plan or answer address that agent; request ids are the agent's own and D7 has no per-send confirmation (design.md:295-296). spec.md:309-313 tests that approval is required, not that it is withheld. Change: for a job with a context job, and its children, require the D14 authentication for `approve-plan` and `follow-up`, or refuse them; keep the derived label on children.

The caller runs as the operator, so mode 0700 (desktop_research.py:100-106) hides nothing from it: `job.json` holds the address whose hash is printed, and a salted hash of a low-entropy account label is confirmable when the salt is readable. Nothing says export file names are generated; a provider-chosen name in a printed path is page text. Change: delete both sentences; state that the boundary covers output only; print generated names and `account_unchanged`, no account hash.
