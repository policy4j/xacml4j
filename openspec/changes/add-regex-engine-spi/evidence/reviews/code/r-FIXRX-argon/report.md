## 2. Verification of the 9 Requested Check Points

1. **Back-references ([XF 1.0 §7.6.1, 23 January 2007](https://www.w3.org/TR/2007/REC-xpath-functions-20070123/#regex-syntax)) (`SUPPORTED`)**:
   - **Normative text fetched**: XF 1.0 §7.6.1 specifies: *"If no string is matched by the nth capturing subexpression, the back-reference is interpreted as matching a zero-length string."* In contrast, OpenJDK 25's `Pattern.BackRef.match` returns `false` when `matcher.groups[groupIndex] == -1`.
   - **Soundness and breadth of [`XfSyntax.checkReferences`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/jdk/XfSyntax.java`)**:
     - Because every `Group` node in [`XacmlPattern`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/XacmlPattern.java`) receives a distinct 1-based group number (`++groups`), `checkReferences` computes exact syntactic dominance on the AST:
       - `Sequence` advances `certain` left-to-right;
       - `Alternation` clones `certain` into each branch (so intra-branch mandatory references like `(a)\1|(b)\2` succeed) and intersects across branches (`common.and(branchGroups)`) on exit;
       - `Group` checks its body (where the group is not yet closed anyway) and sets `certain.set(group.number())` on exit;
       - `Repeat` checks `repeat.atom()` on a cloned `BitSet` (so intra-iteration mandatory references like `((a)\1)*` succeed) and unions into `certain` on exit if and only if `repeat.min() > 0`.
     - Bytecode inspection of JDK 25 `Pattern$GroupHead`, `Pattern$GroupTail`, and `Pattern$GroupCurly` (`javap -c -p`) confirms that when a mandatory group has matched once and a subsequent optional repetition of an enclosing group fails and backtracks, `GroupTail.match` restores the prior `matcher.groups[groupIndex..groupIndex+1]` slots from its stack frame. Thus a group `g` in `certain` is guaranteed to have `groups[2*g] >= 0` whenever `BackReference(g)` is reached.
     - Mandatory captures (`(.)\1`, `^(a)+\1$`) remain supported, and `^(a)?\1$` on `""`, `"a"`, and `"aa"` is pinned in [`RegexEngineContractTest.java:101-105`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/function/regex/RegexEngineContractTest.java`) (`Expect.FALSE`/`Expect.UNSUPPORTED` on `""` and `"a"`; `Expect.TRUE`/`Expect.UNSUPPORTED` on `"aa"`).

## 3. Findings (P1 to P3)

### P3-1 — `XacmlPattern.parseClassEscape` reports `UNSUPPORTED` before checking whether a character-class back-reference is grammatically valid (`[\1]`, `(a[\1])`, `(a)[a-\1]`)

- **Location**: [`XacmlPattern.java:500-502`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/XacmlPattern.java`), [`XacmlPattern.java:607-625`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/XacmlPattern.java`), and [`XacmlPatternTest.java:75, 101-107`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/test/java/org/xacml4j/v30/policy/function/regex/XacmlPatternTest.java`).
- **Problem**: Under [XF 1.0 §7.6.1](https://www.w3.org/TR/2007/REC-xpath-functions-20070123/#regex-syntax), a back-reference `\n` is invalid in the grammar (`Kind.MALFORMED` $\rightarrow$ `syntax-error`) when fewer than `n` capturing subexpressions precede it (`[\1]`) or when the `n`-th subexpression's closing parenthesis has not yet occurred (`(a[\1])`). Likewise, under [XML Schema Part 2 Appendix F production `[20] charOrEsc ::= XmlChar | SingleCharEsc`](https://www.w3.org/TR/2004/REC-xmlschema-2-20041028/#nt-charOrEsc), a `backReference` (`[23] charClassEsc`) is not a `SingleCharEsc` and cannot be the endpoint of a character range (`(a)[a-\1]`). Because `parseClassEscape` unconditionally throws `RegexCompileException.unsupported("back-reference in a character class", "xf parser")` on `c >= '1' && c <= '9'` and is also invoked for range endpoints at line `622`, `[\1]` (with no group 1), `(a[\1])`, and `(a)[a-\1]` report `Kind.UNSUPPORTED` (`processing-error`) instead of `Kind.MALFORMED` (`syntax-error`).
- **Fix**: In `parsePosCharGroup` (`XacmlPattern.java:607-610`), when `peek()` is `'1'..'9'`, call `parseBackReference()` first (which validates `group <= groups && closed[group]` and throws `MALFORMED` otherwise) and then throw `RegexCompileException.unsupported("back-reference in a character class", "xf parser")`; in `parseClassEscape` (reached at range-end line `622`), leave `'1'..'9'` to fall through to `MALFORMED`. In `XacmlPatternTest.java:75, 105`, keep `"[\\1]"` in `grammarRejects` and test `"(a)[\\1]"` in `backReferenceInCharacterClassIsUnsupported`.

### P3-2 — `LiteralBinder` and `XacmlPattern.prepare()` can be package-private

- **Location**: [`LiteralBinder.java:39-51`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/LiteralBinder.java`), [`DefaultFunctionInvocation.java:325`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/DefaultFunctionInvocation.java`), [`XacmlPattern.java:83-85`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/XacmlPattern.java`), and [`RegExpFunctions.java:387`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/RegExpFunctions.java`).
- **Problem**:
  1. `REPORT-FIX-RX-terra.md:48` states that `LiteralBinder` is public because its producer and consumer are in different packages, but both its sole producer ([`RegExpFunctions.Matching`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/RegExpFunctions.java`)) and its sole consumer ([`DefaultFunctionInvocation`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/DefaultFunctionInvocation.java`)) are in `org.xacml4j.v30.policy.function.impl`. Nothing in `org.xacml4j.v30.policy.function` references `LiteralBinder` (`FunctionSpecBuilder.java:480` calls `DefaultFunctionInvocation.bind(FunctionSpec, Value<?>)`).
  2. [`XacmlPattern.prepare()`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/regex/XacmlPattern.java`) has a single caller ([`RegExpFunctions.Matching.<init>`](`.ntm/worktrees/xacml4j--batch2/agyx_1/xacml-core/src/main/java/org/xacml4j/v30/policy/function/impl/RegExpFunctions.java`)). Because `XacmlPattern` is loaded only when the `xf` profile is used, calling `UnicodeSets.prepare()` from a `static` initializer in `XacmlPattern` (or when `XF_READY` compiles `"\\d"` in `RegexProfile.XF`) warms the tables without adding a public `XacmlPattern.prepare()` method.
- **Fix**: If `LiteralBinder` is not intended as a public SPI for third-party `@XacmlFunctionProvider` classes, either move `LiteralBinder` to package-private in `org.xacml4j.v30.policy.function.impl` or have `DefaultFunctionInvocation` dispatch on package-private `RegExpFunctions.Matching.bind(String, Value<?>)`; and replace `public static void XacmlPattern.prepare()` with `static { UnicodeSets.prepare(); }` in `XacmlPattern`.
