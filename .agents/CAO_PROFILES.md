# xacml4j CAO profiles and NTM personas

The CAO profiles in `.agents/cao-profiles/` and the NTM personas in
`.ntm/personas.toml` are generated by `scripts/gen-cao-profiles.py`; edit
the script, not the generated files, then run
`rtk python3 scripts/gen-cao-profiles.py`. CAO loads that directory through
`agents.extra_dirs` in `~/.aws/cli-agent-orchestrator/settings.json`, and it
treats every `.md` file there as a profile, so this document lives outside it.
How to run swarms with these profiles: docs/ai/SWARMS.md.

## Permission modes

Access `read` = no file writes; `plan-write` = OpenSpec artifacts
(including research and evidence) and beads only; `build-write` = writes in
the category's scope (tests or benchmarks) plus Maven builds; `impl-write` =
the files the task packet names, including production code, plus Maven
builds.

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | 
| planner | plan-write | acceptEdits | acceptEdits | acceptEdits | acceptEdits | acceptEdits | acceptEdits | bypassPermissions | acceptEdits | bypassPermissions |
| conductor | plan-write | acceptEdits | acceptEdits | acceptEdits | - | - | - | - | - | - |
| implementer | impl-write | acceptEdits | acceptEdits | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | acceptEdits | bypassPermissions |

| code_review | read | plan | plan | plan | plan | plan | plan | bypassPermissions | bypassPermissions | bypassPermissions |
| test_writer | build-write | acceptEdits | acceptEdits | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | acceptEdits | bypassPermissions |

| jmh | build-write | acceptEdits | acceptEdits | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | bypassPermissions | acceptEdits | bypassPermissions |

Enforcement differs by provider:

- Claude (`plan`) and Codex (`plan`, read-only sandbox) enforce read-only.
  Codex `acceptEdits` limits writes to the workspace; Codex
  `bypassPermissions` has no sandbox (Maven needs `~/.m2` and the network).
- Exception: Codex exec-policy rules with `decision="allow"` run a matching
  command outside the sandbox without asking. The user rules in
  `~/.codex/rules/default.rules` allow bare `rtk bash`, `rtk git`,
  `rtk mvn`, `rtk gh`, and `rtk pkill`, so a Codex agent that prefixes
  commands with `rtk` escapes `plan` and `acceptEdits` confinement (seen in
  an NTM pane on 2026-09-30). Until those rules become `prompt` or
  `forbidden`, Codex read-only lanes are read-only by prompt only.
- Grok enforces the tool list: read-only profiles have no Edit/Write tools.
- Kimi and Agy cannot enforce tool restrictions under CAO; their read-only
  rule is prompt-level. Kimi needs `bypassPermissions` for CAO callbacks.

Use them from the repository root with `NTM_PROJECTS_BASE` set
(docs/ai/SWARMS.md):

- `ntm spawn policy4j --label <label> --persona=policy4j_code_review_claude_opus --persona=policy4j_code_review_codex_astra`
- `ntm spawn policy4j --label <label> --profile-set policy4j-review-team --grok=1:grok-4.7:xhigh --kimi=1:kimi-code/k3`

Limits:

- NTM enforces no read-only access; review personas are read-only by prompt.
- Claude and Codex panes load the persona prompt at launch (smoke tests
  2026-09-29 and 2026-09-30). Send the role with every packet to Agy, Grok,
  and Kimi panes: `ntm send <session> --pane=<n> --base-prompt-file
  .ntm/roles/policy4j_<category>.md --file <packet>`.
  - Codex needs the NTM `[agents] codex` launch template to pass the
    prompt as `-c developer_instructions="$(cat <prompt file>)"`. NTM's
    stock template uses `CODEX_SYSTEM_PROMPT`, which Codex ignores; on a
    machine with the stock template, send the role to Codex panes too.
  - Grok and Kimi have no persona: NTM refuses Grok personas (no
    system-prompt flag it can use) and runs Kimi only as a plugin. Spawn
    them with the flag above.
  - Agy: the persona prompt goes in as the first interactive prompt, and a
    first launch in this directory stops on Antigravity's trust prompt until
    someone answers it in the pane.
- NTM conductors are Claude only; Codex's workspace-write sandbox is not
  expected to allow driving tmux through `ntm`.
- NTM pins its Antigravity agent to Gemini 3.8 Flash (High), so the `agy`
  personas run that model, not the CAO profiles' Gemini 3.1 Pro (High). For
  Gemini 3.1 Pro under NTM, spawn `--agyx=1:gemini-3.1-pro-high` and send the
  role with `--base-prompt-file`.

## CAO usage

- From a conductor: `assign` or `handoff` with the profile name, and put
  the conductor terminal id and the task packet in the task.
- From a driver: `cao launch --agents <name> --session-name <name>
  --working-directory <repo root> --headless --async "<task>"`, or the CAO
  ops MCP `launch_session`. Conductor profiles also need the
  `mcp__cao-mcp-server__assign`/`handoff`/`send_message` tools in the
  launch's allowed tools when they run on Codex.

## Known issues

- Grok (`grok_cli`): every CAO launch starts with a fresh Grok home, so Grok
  asks "Do you trust the contents of this directory?", and CAO deliberately
  does not answer it. CAO also misreads Grok's idle home screen as
  processing, so its startup check never passes. The profiles set
  `provider_init_timeout: 3600`; an operator answers the trust prompt and
  types the task into the Grok terminal. Fixing the provider's
  `PROCESSING_PATTERN` in CAO removes the second problem.
- The code-intelligence MCP servers (Serena, ast-grep, ripwire) are declared
  once per CLI: `.mcp.json` (Claude, Kimi, Copilot), `.codex/config.toml`
  (Codex), and `.grok/config.toml` (Grok). Keep the three files in step.
  Agy has no project MCP file; Agy agents use the CLI forms in AGENTS.md.
  Approve the servers once per checkout so headless launches do not stop on
  the approval prompt.
- Serena starts on first use and stops when idle. When an agent exits, it
  can end the Serena that other agents share; repeat the call, and it starts
  again.
- Codex `plan`/`acceptEdits` profiles can call only the CAO callback tools;
  other MCP tools are rejected by Codex's approval policy.
